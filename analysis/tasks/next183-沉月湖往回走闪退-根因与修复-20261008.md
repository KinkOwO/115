# 沉月湖「清理完 2 个图后往回走」闪退 —— 根因与修复（2026-10-08）

> 业主：「沉月湖副本一阶段清理完 2 个图后往回走会闪退，我最新一轮的日志已经复现」
>
> **结论：已定位并修复。** 根因是**往回走时 `MoonSoloOwner.StartMap` 没发 `ReuseRoom`**，
> 客户端收到「既不重建也不复用」的包后，去 draw 一批已经失效的缓存对象 ⇒ `0xC0000005`。
> 带守卫用例，`internal/dungeon` 全量通过。

## 2. 根因

`cmd/wireprobe/moon_solo_flow.go` 的 CMD45 分支（656-673）：

```go
case 45:
    request, e := protocol.DecodeDungeonRoomTransition(p)
    ...
    if e = r.Move(*w.dungeons, request, seed, now); e != nil { return fail(e) }
    w.activeDungeon = r.Session()
    body, e := r.StartMap()                       // ← moon_map (NOTI29)
    return true, []outboundPacket{{"moon_move_ack", 1, 45, []byte{1}}, {"moon_map", 0, 29, body}, w.moonInfo(2, false)}, nil
```

`internal/dungeon/moon_solo.go` 的 `MoonSoloOwner.StartMap()`（改前）：

```go
var fixed []protocol.DungeonMonster
for _, m := range s.LivingMonsters() {
    if _, dynamic := s.MoonDynamic[m.Entity]; !dynamic { fixed = append(fixed, m) }
}
p := protocol.StartMapState{Position: ..., Seed: r.seed, Map: s.Room.Map, Monsters: fixed}
```

**⇒ 它从不设 `ReuseRoom`。**

「往回走」= `moveMoonSecondFloor` 判定 `forward == false` ⇒ 走通用 `s.Move` ⇒ `enterRoom`
⇒ 该格已清完（怪都被 carry 走了）⇒ `LivingMonsters()` 为空 ⇒ `fixed` 为空
⇒ 发**「普通路径 + 0 怪」**。

**而普通副本路径早就有这条规则**（`cmd/wireprobe/dungeon_flow.go` 的三处 `ReuseRoom` 决策），其中第③条正是这个语义：

```go
if _, visited := w.activeDungeon.Visited[next.Room.Map]; visited && (Odyssey || IsResumedSceneBase() || IndividualMapMovement...) {
    state.ReuseRoom = true
    state.Monsters = nil
}
```

`internal/game/protocol/dungeon.go` 的 `StartMap` 注释也写明了这个形态的原生依据：

```go
// Native1452b78f0 skips map/spawn rows for mode0. The constructor at
// 145b235b0 then retains the cached map and its one-shot ACT triggers.
if s.ReuseRoom { return append(p, 0, 0, 255), nil }   // mode0
```

**⇒ 客户端收到 mode0 时会「保用缓存的地图」；收到普通路径则按新房间重建。**

**⇒ 沉月湖这条线漏了这条规则：往回走发普通路径 ⇒ 客户端**既没有重建**（包是空的）**也没有复用**（没给 mode0 信号）⇒ 它缓存里那批 (0,1) 的对象指针已失效 ⇒ draw ⇒ 崩。**

旁证：`MoonSoloOwner` **本来就有 `reuseRoom` 字段**，但只有「读」和「重置」两处接线
（`moon_room.go:23 if r.reuseRoom { return nil, nil }`、`moon_floor.go:59 r.reuseRoom = false`），
**没有任何一处把它置 true** —— 是一条没写完的路径。

同源先例：`internal/dungeon/scene_transition.go:479` 的注释
「同图再进同图，StartMap 发 ReuseRoom 而客户端没有该图的缓存 —— **直接崩溃**」
⇒ 反过来正是：**客户端的该图有缓存时，ReuseRoom 才是正确形态**。

## 3. 修法（`internal/dungeon/moon_solo.go`，+23 行）

1. `Move()`：在调 `moveMoonSecondFloor` **之前**取 `prev := r.session.Visited`，之后
   `_, revisited := prev[next.Room.Map]; r.reuseRoom = revisited`。
   ⚠️ **判据必须取「移动前」的快照** —— `enterRoom` 会重建 `Visited`，移动后每个格子在
   `Visited` 里都成立，拿移动后的判会恒真。同图往返（目标图 == 当前图）也被这条一并覆盖。
2. `StartMap()`：`if r.reuseRoom { p.ReuseRoom = true; p.Monsters = nil }`。

与实机 trace 形态一致（实机 224 B / 48 B，差在 map 与怪数）。

### 4.2 守卫用例

`internal/dungeon/moon_backward_revisit_test.go` —— `TestMoonSoloBackwardRevisitReusesCachedRoom`：
前进两格**必须**是普通路径（带怪物行），往回走**必须**是 ReuseRoom 形态。
判据用协议层确定的形态（固定 31 字节前缀后 mode0 的 `00 00 ff`、总长 34），
**不是**只看尾三字节 —— 实测普通包尾部也可能凑巧是 `00 00 ff`（217 B 那包就是）。
