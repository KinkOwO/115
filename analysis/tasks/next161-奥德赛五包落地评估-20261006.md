## 五、风险与需要拍板的三件事

### 5.1 ★ 包间语义冲突：红柱文档警告"不要动 2856"，而 4125 恰恰删了它

- 红柱 `00-修复说明.md` §三.2 明写：「**不要为「通关时奖励公告弹窗」去动 2856**（同日另一条取证已实机证明通关时的 NOTI2856 是章节完成/退图 load-bearing 包，**删它会卡图**）」。
- 而 4125 包的全部内容就是「删 `completeDungeon` 的 2856 + `leaveDungeon` 补发 2856」，且**已实机确认「完美」**。
- 交付链时序上 4125 在红柱**之后**（4125 的旧基线 `9eaea33d` = 红柱的产物），且后续的 CMD38/层图格/毕业三个包**都保留了** 4125 的改动 ⇒ **以 4125 为准**，红柱那句是被推翻的早期结论。
- ⚠️ 但这是"删一条已在跑的包"的改动，落地时必须单独实机验：通关章节末本 → 4125 弹；回城 → 地图即时刷新；**且退图不卡**。

### 5.2 毕业包的存储层要重写（不是移植）

`internal/database/odyssey_graduation.go` 与两个 `max_level_reward*.go` 在交付方是 **pgx 形态**；我方 `go.mod` 已无 `jackc/pgx/v5`（`internal/database/sql` 只剩 `sqlite`）。
移植面很小、语义清楚，但必须逐行改写：

| 交付方（PG） | 我方（现行） |
| --- | --- |
| `s.db.Begin(ctx)` / `tx.Rollback(ctx)` / `tx.Commit(ctx)` | `s.engine.begin(ctx)` / `tx.rollback(ctx)` / `tx.commit(ctx)` |
| `sqlcgen.New(tx)` | `tx.queries()` |
| `s.queries.WithTx(tx)` | `tx.queries()` |
| `errors.Is(err, pgx.ErrNoRows)` | `isNoRows(err)` |
| 导入 `github.com/jackc/pgx/v5` | **删掉** |

保留的**语义**只有两块：`OdysseyGraduationEvent` 改 **v3** + `compensatedPriorEvent`(v2) 的 `ClearQuests` 补偿分支；以及 `CommitMaxLevelRewardMail` 的每角色一次性收据（事件键 `max-level-reward-mail-v1`）。

### 5.3 CMD38 的删除幅度要实机回归

`interactDoor` 全仓**生产调用点只有 1 个**（`client_dispatch_world.go:372` 的 case 38），其余 21 处都是测试 ⇒ 删除面干净。
但包自己在 §六 留了尾巴：**引导副本 7113（祭司 Priest）此前靠 `interactDoor` 硬编码推进，删掉后未实机验证原生 CMD45 是否走通**，用户当时决定暂不处理。落地后若引导卡门，第一个回查项就是这里。
