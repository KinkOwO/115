### 2.1 这些是从哪来的（初步定位）

小深渊 `.dgn` 自己写着（`runtime/pvfdgnone/00-endkeeperoforder.dgn.txt`）：

```ini
[difficulty dropitem group list]
[group info]
[item index] 10326880 10326884 10419088 10419090
[normal group index] 1 21251 1 21476
[special setinfo reward] 320 10326880 1 21279
…
[/group info]
```

而 `bin/dropgroup.exe` dump 出来的两份组：

- **21251** = `smart_drop_item` **全是 662 新手套**（`100051304 Starter Training Top` … `100391038 Starter Voice`，各 weight 10），
  `creation_rate [0,0]`；
- **21250** = 一批通用装备（42 件，各 weight 30），`creation_rate [1085,0]`；
- **21476** = `drop_item` 只有 `10419716`（`Endkeeper of Order Expected Reward` 礼盒，weight 1）。

⇒ **实测掉到的 662 新手套正好就是 21251 的内容** ⇒ 我们把 `[normal group index]` 里的 21251 当「该掉的组」用了。
但官方池清单里没有新手套；而且 21251 的 `creation_rate` 是 **[0,0]**（21250 是 [1085,0]）——
**`creation_rate` 很可能就是「这个组会不会生成的几率」**，取 0 就不该出。

### 2.2 另外两件（复活币 / 金库升级道具）

它们不在 21251/21250/21476 的 dump 结果里，需要再定位：要么在**别的组**、
要么来自 `smart_drop_item` 之外的字段、要么来自我们的**通用掉落链**（`ordinary source pool`）。
业主若能看到它们**具体是从哪个副本/哪次掉落**出来的，定位会快很多；
也可以先按「名字白名单」把它们从深渊的候选集里剔掉（见 §3）。

已 dump `OrderOfTheBorder_Legendary/Epic.dgn`（`runtime/pvfdgnborder/`）核对这一点。

## 5. 代码侧与 dgn 侧的补充事实（2026-10-07 20:25）

### 5.1 大深渊的 `[hunt boss]` **是有的** —— 嫌疑往后挪

`runtime/pvfdgnborder/`：

```ini
; OrderOfTheBorder_Legendary.dgn (100005067) 与 OrderOfTheBorder_Epic.dgn (100005068)
[dungeon type] `boundary of attunement`
[clear condition]
[hunt boss] 109008634 1
[/clear condition]
```

⇒ `SourceBoss = 109008634 ≠ 0`，**§4 里「SourceBoss==0 导致不触发」的假设不成立**。
下一层嫌疑（按 `internal/dungeon/completion.go:280-282` 与专属奖励的判据）：

- 该模板必须**真的以 `Rank == 3`、`Team != 0`、非 NonCombat 的身份**出现在大深渊的房间里；
- 且专属奖励只认「这次死亡」这一事实（`s.Dead[entity]`）。
⇒ 下一步要 dump 大深渊的地图，核对 `109008634` 的生成与 rank。

### 5.2 深渊这条链在代码里是**独占**的

```go
func preserveAbyssDrops(c, attunement, dungeonID) bool {
    if c.IsAbyssDungeon(dungeonID) { return true }          // 小深渊这类
    for _, id := range attunement.Dungeons() { if id == dungeonID { return true } }  // 表里那 7 个
    return false
}
func ordinaryDungeonRewards(...) bool { return d != nil && !d.Definition.Odyssey && d.HellPosition == nil && !preserveAbyssDrops(...) }
```

⇒ 深渊副本上**普通掉落链是关掉的**（`ordinaryGroups`、`monsterItems`、清关奖励都不走）。
**所以实测掉到的 662 新手套/通用装备，不可能是「普通链」给的** —— 它们只可能来自
**rewardboostinfo（CTP）表本身**，或来自 CTP 里那些**礼盒被「开一层」之后露出来的内容**
（启动日志原话：`attunement reward wrappers open one layer; 1 empty-face templates: [12]`）。

⇒ 业主点名的「复活币 / 金库升级道具」若确实从深渊掉出来，最可能就是**在 CTP 的某个礼盒内部**。
正在用 `ctpdump` 直接 dump `etc/rewardboostinfo/endkeeperoforder/normal.ctp` 核对。

### 5.3 `[normal group index]` 与 `creation_rate`

`bin/dropgroup.exe` 对 dgn 声明的那几个组的读数：

| 组 | 内容 | `creation_rate` |
| --- | --- | --- |
| 21250 | 42 件通用装备（各 weight 30） | `[1085,0]` |
| **21251** | **662 新手套**（各 weight 10） | **`[0,0]`** |
| 21476 | `drop_item` 只有 `10419716 Endkeeper of Order Expected Reward` | — |

实测掉到的 662 新手套 = 21251 的内容。**21251 的 `creation_rate` 是 `[0,0]`** ——
若该字段确为「这个组会不会生成」的几率，则它本就不该产生掉落。
⇒ 两条并行验证：① 我们是否把 21251 当「该掉的组」用了；② `creation_rate` 的语义（用一份能对上官方清单的副本来定）。
