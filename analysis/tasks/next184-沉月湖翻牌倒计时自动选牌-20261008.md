# 沉月湖翻牌：倒计时结束不自动选牌（2026-10-08）

> 业主：「通关翻牌如果玩家倒计时结束没有选不会帮玩家自动选择第一个牌子」
> （承接同轮的「沉月湖往回走闪退」，那条已修复；见 `next183`）
>
> **结论：已定位并修复。** 沉月湖的翻牌走 `dispatchSpecialContent → moonHandle`，
> **绕过了** `dispatchDungeon` 里那段「`card_layout_ack` 时置自动选牌计时器」的后处理；
> 而且通用的 `autoPickSettlementCard` 与沉月湖**不是同一条领取路径**，不能直接复用。

---

## 1. 现场（会话 `roles_persist_..._20261008_233707_020134_next37`）

通关到翻牌这一段（`events.jsonl`，时间为 UTC）：

```
15:41:34.063 moon_info + monster_death_confirmed + moon_info
15:41:34.064 dungeon_clear_enabled (31)            ← 二层通关
15:41:34.139 client_frame id=46 (141 B)            ← 客户端索取结算
15:41:37.153 moon_clear_reward (35)                ← 服务端发翻牌奖励
15:41:37.186 client_frame id=69 → card_scroll_ack
15:41:37.939 client_frame id=70 → card_layout_ack  ← 翻牌布局发出（此后应开始 3 秒倒计时）
15:41:45.702 client_frame id=309 (13 B, body 空)   ← 之后**服务端再无任何 S→C**
15:41:57.735 … 15:42:57.756  只剩 sec_ping_check_sent / id=1706 心跳
```

- 全场**没有** `id=71`（玩家选牌）也没有 `id=72/42`（离场）⇒ 玩家确实**没选**；
- 服务端在布局发出后**一帧都不发** ⇒ 倒计时结束后什么都不会发生。

## 2. 根因

### 2.1 分派路径不同：沉月湖不经过那段后处理

`cmd/wireprobe/client_dispatch_world.go` 里，**通用副本**的翻牌在 `dispatchDungeon`：

```go
case 69, 70:
    plan, e = client.worldState.cardStage(requestData.frame.ID, requestData.plaintext)
...
for _, p := range plan {
    if p.Name == "card_layout_ack" {
        // 布局发出后给玩家 3 秒选牌；到点还没选就替他选第一张（见 autoPickSettlementCard）
        if !client.worldState.cardLayoutSent && client.worldState.cardReceipt == nil && client.worldState.activeDungeon != nil {
            client.worldState.cardAutoPickAt = time.Now().Add(3 * time.Second)
        }
        client.worldState.cardLayoutSent = true
    }
    ...
}
```

**而沉月湖**走 `dispatchSpecialContent`（同文件 140-166）：

```go
handled, packets, e = client.worldState.moonHandle(requestData.frame.ID, requestData.plaintext, time.Now(), client.event)
if handled {
    ...
    if client.sendPlan(packets, func(packet outboundPacket) {
        client.event(map[string]any{"kind": packet.Name, "id": packet.ID})   // ← 只记事件
    }) != nil { return dispatchClose }
    return dispatchHandled
}
```

⇒ 它**只记事件**，**没有** `cardAutoPickAt` 那段 ⇒ 沉月湖的 `cardAutoPickAt` **永远是零值**。

### 2.2 领取路径也不是同一条（所以不能直接复用通用函数）

| | 通用副本 | 沉月湖 |
| --- | --- | --- |
| 奖单 | `w.cardPlan`（`*loot.CardPlan`） | `w.moon.plan`（`*loot.MoonRewardPlan`） |
| 前置校验 | `cardsReady()`（要 `cardPlan != nil`） | `w.resultSent && w.moon.plan != nil` |
| 落袋 | `grantFreeCard(index)` | `moonClaim(index)` |
| 落袋帧 | `card_inventory_committed(13)` + `card_selection_ack(71)` | `moon_reward_inventory(13)` + `card_selection_ack(71)` + `moonInfo(5,true)` |

⇒ 通用 `autoPickSettlementCard` 的前置 `cardsReady()` 对沉月湖**必然失败**
（`cardPlan` 是 nil），所以**不能**简单地把 `cardAutoPickAt` 指过去 —— 必须单开一条同形函数。

## 3. 修法（3 文件，+68/−1）

1. **`cmd/wireprobe/moon_solo_flow.go`**
   - `moonSoloState` 新增 `autoPickAt time.Time`；
   - `case 69, 70` 的 `id == 70` 分支：`if !w.cardLayoutSent && !w.moon.claimed && w.moon.plan != nil { w.moon.autoPickAt = now.Add(3 * time.Second) }`
     —— 与通用路径同款判据、同款 3 秒；
   - 新增 `autoPickMoonCard(now)`：到点 + `owner != nil` + `plan != nil` + `!claimed` + `cardLayoutSent` + `resultSent` + `activeDungeon != nil`
     ⇒ `moonClaim(0)`；前置不满足则**清掉计时器**（免得每 tick 空转）；领取失败（如满包）则 5 秒后重试。
2. **`cmd/wireprobe/client_connection.go`**：同一个 ticker 里紧接通用自动选牌之后调用
   `autoPickMoonCard`，两份包合并一次 `sendPlan`。

## 5. ★ 与「通关后似乎无缝回城」的关系（待业主确认）

同一条会话里把回城类帧全体统计了一遍：

| kind | 次数 |
| --- | --- |
| `moon_town_state` / `moon_town_actor` / `moon_town_attributes` | **0** |
| `dungeon_return_area` / `dungeon_return_users` | **0** |
| `dungeon_leave_ack` | **0** |
| `moon_clear_reward` | 1（15:41:37） |
| `moon_info` | 116（最后一条 15:41:37.154） |

**⇒ 服务端从未发过任何回城帧**，翻牌后直到会话结束只有心跳。

**推断**：倒计时结束后服务端什么都不发，客户端**自己**处理了退场（画面上表现为「无缝回城」）。
若如此，则**与问题 1 同源** —— 补上自动选牌后客户端会收到 `card_selection_ack(71)`，应不再自行离场。

**⚠️ 待确认**：如果补上自动选牌后「无缝回城」仍在，请描述具体表现（是「自动跳回城镇」还是
「少了某段演出/结算」），以及是发生在**哪一次通关**（一层 100004136 还是二层 100004137）。
届时按 002 形的「该发的帧有没有发出去」重新定位。
