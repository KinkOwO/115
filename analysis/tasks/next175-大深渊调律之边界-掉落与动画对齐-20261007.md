大深渊（传说 100005067 / 史诗 100005068）的 dgn 要点：

```ini
[maze info] [size] 1 1 [maze chance rate] 990000 / 9143 / 857   ← 史诗有三个 maze
[clear condition] [hunt boss] 109008634 1
[dungeon type] `boundary of attunement`
[direct eplp on clear dungeon]           ← 与小深渊同款的无缝续刷声明
[difficulty dropitem group list]
  [item index] 10326880 10326884 10420247/48/49 10419754
  [normal group index] 1 21251 1 21600 / 21601 / 21602
```

组 `21600/21601/21602` = 只掉一件：`10420063/10420064/10420065`
= **`Material Expected Reward Booster`**，其内容（等权 1000）为：
**银币 + `10400396 Void Soul` + 四档 `Will of Splendor`** ⇒ 与官方「虚无之魂 ×3/4/5 + 光辉意志」**逐条吻合**。

`etc/rewardboostinfo/skyofathousandseasofborder/epic.ctp`（100005068）：

```
[fixed drop table] ×3（maze 0/1/2） 每个 [drop list] 都是：
    epic 914300 → 10419728      primeval 85700 → 10419729
[additional drop table] ×14
[hidden drop table] ×2（maze 1 / maze 2）
    结构 = [maze] N + 若干 [drop list]，每条是 12 项 (index 0..11 → 物品) 的**选择列表**
    （index 不是权重，所以我们的解析器把它当"未定触发条件"搁置了）
```

**⇒ 动画↔掉落的对齐规则（官方原话）**：
**珠子由入场材料（传说/史诗调律砝码）决定，并保证掉落「对应稀有度以上」。**
传说 ⇒ 保底 传说~太初；史诗 ⇒ 保底 史诗~太初。

## 6. 本轮落地（2026-10-07 21:00）：G1 + 真正的根因修复 + 两个顺带

### 6.1 ★ 根因：**源表的档位词表里有客户端不认识的档位**

把四张 CTP 的档位标签全枚举出来：

| 表 | 档位词表 |
| --- | --- |
| 小深渊 `endkeeperoforder/normal.ctp` | normal / rare / unique / legendary / epic / primeval / **luck15 / luck30** |
| 传说 `skyofathousandseasofborder/legendary.ctp` | legendary / epic / primeval / normal / rare / unique / **voidsoul** |
| 史诗 `skyofathousandseasofborder/epic.ctp` | epic / primeval / … / **voidsoul / primestella** |

我们只认 8 个标签（normal/rare/unique/legendary/epic/primeval/luck15/luck30）。
`voidsoul`（虚无之魂）与 `primestella`（太初星蕴石）**不在其中** ⇒ `TierGradeValue` 返回 **0**
⇒ `PlanRun` 里 `out.Oath = 0` ⇒ `RollPlanned` 的 `if tiers.Oath != 0` **把整条附加奖励跳过**。

⇒ **实机表现就是「动画出了太初特效、地上却什么都没有」。** 与业主症状逐字吻合。

**修法（按源表付，不猜客户端语义）**：

| 文件 | 改动 |
| --- | --- |
| `internal/loot/attunement_plan.go` | `RunTiers` 新增 `PrimerLabel` / `OathLabel`（源表标签）；`PlanRun` 记录标签；`RollPlanned` 改为「档位非 0 或标签非空都要付」；新增 `plannedTier()`（档位能反查就用档位，反查不到退回标签）与 `oathEntryByTier()`（按标签反查分支/条目） |

档位值（2838 给客户端看的那个数字）**不动** —— 语义未定就不猜；掉落不再凭空消失才是这一步的目标。

### 6.2 G1：大深渊的 maze 几率导入

`configs/dungeons.maze-chance-rates.json` 追加：

```json
{"id":100005068,"dungeon_sha256":"52810da52a566db5",
 "source_rates":[990000,9143,857],"rates":[990000,9143,857],
 "provenance":"… 从 OrderOfTheBorder_Epic.dgn 的 [maze chance rate] 原样导入；只有 maze 1/2 带
   [hidden drop table]，所以这里不做倾斜，测试用 DFO_MAZE_FORCE=100005068:1"}
```

- 传说（100005067）是**单一 maze（1000000）**，本来就不需要选图；
- 史诗（100005068）三个 maze：**990000 / 9143 / 857**；
- 原样导入不做倾斜：**maze 1/2 才是带 `[hidden drop table]` 的那两个**，
  要验证它们用诊断开关 `DFO_MAZE_FORCE=100005068:1`（或 `:2`），不必硬刷 1%。

### 6.3 顺带修掉：2838 的档位兜底是 **0/0**，不是注释里写的 normal/normal

`TestOathInfoPacketsFallsBackToNormalWithoutPity` 一直在失败：
`oathInfoPackets()` 在「没有活动表」时下发 `0/0`，而 0 **不在客户端那 8 档阶梯里**
（40..45 / 70 / 71），代码注释却写着「下发 normal/normal」。
现已折成 `inventory.OathGradeNormal`(40) 再下发（`cmd/wireprobe/oath_info.go`）。

### 6.4 ⚠️ 工具链陷阱：启动器会把 dev-local 的旧 fixture 拷回 testdata

`调试启动-本地构建.cmd` 里有

```
copy /y "runtime\dev-local\config_help.json"  "cmd\wireprobe\testdata\config_help.json"
```

**所以改 fixture 必须同时更新 `runtime/dev-local/` 里的快照**，否则下次启动就被覆盖回旧版
（本轮实测：我改好的 fixture 被旧快照覆盖 ⇒ 配置契约测试失败）。
另外那个 GUI 启动器还会**清空 dev-local**（连 `config_help.json` 一起没了）。
⇒ 已把 dev-local 用当前 `bin/` + `testdata/` 重新同步齐（5 个文件）。
