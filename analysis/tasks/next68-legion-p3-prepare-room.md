## 2. 本轮新取证（IDA，`p3-survey/` 与 `va-decompile/`）

### 2.1 CMD2045 的字段与回包（`sub_1424FE290` / `sub_1424FD160`）

- **C2S**：`int32@13` + `int32@17`，21 字节。字段语义由客户端的作战界面确认分支钉死：
  `sub_1424FE290(107, *(a1 + 115))` ⇒ `@13` = **107 通道码**、`@17` = **作战 id**。
- **S2C**：handler 读 13 字节，**只看首个 dword 作结果码**：

  | `@0` | 客户端行为 |
  | --- | --- |
  | `0` | 什么都不做（成功） |
  | `252` | 显示本地化串 725 |
  | `380` | 显示本地化串 101037339 |
  | 其它 | 显示串 101037339 的同族提示 |

  ⇒ **成功 = 13 字节零**。另外三个字段（`@4`/`@8`/`@12` 的读前初值为 108 / -1 / 0）在成功路径上**未被使用**，因此留零而不是假装有含义。

### 2.2 CMD2355 的字段与回包（`sub_14069E3B0` / `sub_14069E320`）

- **C2S**：`int32@13`（**职责值**）+ `int32@17`（107），21 字节。
  字段语义由调用者 `sub_14069B4E0` / `sub_140697C30` 钉死：

  ```c
  if (sub_1459A90F0(qword_14E66C090) != 3 || …) return 0;   // 要求 world state == 3（副本态）
  v9  = (*(…)(*v8 + 8656))(v8);                             // 取槽位索引 0..3
  v10 = v9 > 3 ? -1 : *(_DWORD *)(a1 + 4*v9 + 211);         // 该槽位当前职责
  if (a2 == v10) return 0;                                  // 没变化就不发
  sub_14069E3B0(a2);                                        // 发 2355
  ```

  ⇒ 2355 是**边沿触发**的「玩家改了职责」通知（不是轮询），职责按**槽位索引**存于 `a1+211+4*idx`
  （索引 0..3 ⇒ 最多 4 个槽位）。
- **S2C**：`sub_14069E320` 是裸转发——只清「期望回包树」并把请求转给界面对象，
  **不读游标** ⇒ body 为空，只有 opcode 有意义。

### 2.3 两个主动下发包的取证结果（**结论是「先不发」**）

**`NOTI2568`**（16 字节）：
- 客户端初值常量 `xmmword_1494B7AE0` = `00000000 00000000 ffffffff 00000000`
  ⇒ 默认结构：`@0`=0（成功）、`@4`=0（模式）、`@8`=-1、`@12`=0。
- handler `sub_1424FE000`：`@0 != 0` → 显示串 145；`@0 == 0` 时若 `@4 == 1` 则调
  `sub_146D0D2A0(registry, @12, @4)`。
- **投递方 `sub_146D0D2A0` 是 toggle**：以 `a1+1416` 为标志，已置位即走「关闭」分支（串 18670），
  未置位走「打开」分支（串 18613）。⇒ **条件未闭环时重复下发会把准备界面关掉**。
- 因此本轮**不主动下发**，登记为 §6.2 **X5**。

**`NOTI2254`**（256 字节）：
- 结构 = **7 个 24 字节成员槽位**（`7 × 24 = 168`）+ 84 字节 `0xFF` 尾部哨兵
  （哨兵常量 `xmmword_1491B4820` = 16×`0xFF`）。消费者 `sub_142ABF5E0` 只把整块拷进
  `qword_14E683C40 + 32`，**不做解释**。
- 客户端默认构造器 `sub_1424FD050` 揭示每槽被清的字段：
  `u16@0` / `u64@2` / `dword@10` / `dword@16` / `byte@20`（其余到 24 字节为填充）。
- **但没有"写者"可对照** ⇒ 无法确定哪个字段是角色 id / 名字 / 职业。
  单人队要往槽位 0 填本人，填错后果未知，因此本轮**不主动下发**，登记为 §6.2 **X6**。

## 4. 假设与降级

- `EnterDungeonAck` 只依赖「`@0 = 0` 即成功」这一条已确证的分支，**不假设**其余三字段语义。
- `RoleSelectAck` 空 body 有依据（handler 不读游标），不是省事。
- **X5 / X6 是有意不做**，不是遗漏：两者都已取证到"结构清楚、投递条件不清楚"，
  在条件闭环前主动下发会造成**比不发更糟**的结果（关界面 / 未知渲染）。
