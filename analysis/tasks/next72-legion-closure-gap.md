**协议契约已经 100% 闭环，缺的是「服务端要主动下发的 7 个 NOTI」——目前一个都没发。**

家庭包一共 14 个 S2C handler，其读取长度与守卫条件已全部钉死（`next65` §2.2）；

这四类**都是服务端主动推的 NOTI**，而它们的载荷结构目前只有长度、没有布局。

**X7 本轮新证据**（第二轮探针 `analysis/dumps/ida_phase_x7b.py`）：

```c
sub_142ABF650(a1, a2):
    key  = sub_142AB29C0(a1);                     // 小整数：7/10/17/20/21/27/28 七种取值
    node = rbtree_lookup(*(a1 + 312), key);
    obj  = node[5];
    obj && (*(vtable_of(obj) + 1136))(obj, a2);   // 144 B 块由被调类的 slot 142 解释
```

`sub_142AB29C0` 的取值来自一个 locale/language 访问器 ⇒ **`+312` 的 map 很可能是
「按语言/地区分的处理器表」，不是玩家或阶段 id 的注册表**。这意味着 `qword_14E683C40`
是不是「阶段子系统」本身需要复核 —— 第一种可能是阶段状态机，第二种可能只是一个
本地化消息分发器，2657 只是它的入站消息之一。第二轮探针查「谁还调用这个派发器」
与「谁读这个全局」，用来把这两种可能分开。

## 6. 距离「提 MR」还差什么

按根 `AGENTS.md` §7 与用户 2026-09-22 定调：**验证通过前不提交 MR**。当前 MR 的门槛是：

1. **一次实机**（用户操作）：进城镇 → 触发军团入口 → 选作战 → 确认 → 看准备房间。
   这一次能同时结掉 **X1 / D1a / 2045 之后怎么进本** 三项，并回答 T4。
2. 视第 1 步结果决定 X7 是「必须解」还是「降级为多人同步用」：
   - 客户端自走 ⇒ P4 驱动可标为「单人不需要」，X7 降级；
   - 客户端不自走 ⇒ 必须先解出 144 B 布局才能推进阶段。
3. X9（2895/2896）与 T5（2252/2253）：只要目标包含「界面显示军团信息 / 作战列表」和
   「通关发奖」，就必须解；否则玩法只能到「进本、打、退」为止。

**结论**：协议侧已经做完；剩下的是**四类服务端主动 NOTI 的载荷布局**（X7/X9/T5/X5/X6）
与**一次实机**。其中真正阻塞「跑通一轮」的是 X7 + X9 + 2045 进本归属，其余可以延后。
