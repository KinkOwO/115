# mods —— 服务端层 mod 源码（由 modkit 管理）

本目录下的每个子目录是一个已安装的服务端 mod 的 Go 包，由
`modkit install` 从 mod 包的 `server/` 层落位而来，**不要手改**：
下一次安装/卸载会按注册表重写。

- 每个 mod 目录里的 `.modkit-owner` 是来源标记，卸载靠它确认归属。
- 每个 mod 目录里的 `mod.json` 是**原样搬运**的组织文件副本：
  管理器与 `modkit mods list` 从这里读 名称 / 版本 / **作者 / 说明** / 层 /
  权限 / 依赖 / 钩子。作者与说明写在那份清单里，不要改这个副本。
- **mod 加载器**是 `mods/zz_mods_gen.go`（生成物，见下一节）：它 import 各已装 mod
  并调用它们的 `Register()`；即使本目录为空，服务端也编得过。
- 删除某个 mod：用 `modkit uninstall --id <mod-id>`，不要直接删目录。

服务端侧的钩子宿主在 `internal/servermod`（钩子点与宿主机操作的实现）。

## 加载器 `zz_mods_gen.go`：怎么来的、仓库里为什么是干净形态

**它是什么。** `mods/zz_mods_gen.go` 是 modkit 生成的 mod 加载器（文件头写着
`Code generated by modkit. DO NOT EDIT.`）。它把各**已安装**的 mod 包 import 进来，
再暴露 `RegisterMods()`（服务端 `cmd/wireprobe` 调它），于是"本机哪些 mod 被编进这份
服务端程序"由这个文件决定。它不是数据清单，而是**编译期的加载代码**。

**它怎么被写。** 两条路径，都写"本机这份"：

1. `modkit install/uninstall` 装卸时重写；
2. 启动器每次编译前再按 `<服务端模块>/mods/` 的**目录现状**重算一次
   （启动器仓 `internal/modkit/syncgen.go` 的 `SyncServerModsGen`，编译入口
   `internal/serverbuild`）——判据是"目录里真的有 mod"（有 `.modkit-owner` 或
   `mod.json`），所以本机那份即使被谁改乱、或别人推了一份别的进来，都不影响本机编译。

**仓库里为什么是干净形态。** 加载器同时**进版本库**（不提交的话服务端连
`mods.RegisterMods()` 都没有，mod 就没法用），所以仓库里这份必须是**不 import 任何
mod 的干净形态**：只有它才保证「谁 clone 下来 `go build ./...` 都编得过」。
反例就是本目录曾经的提交形态 —— 加载器里写着 `dfolan/mods/odyssey.hardcore`，而那份
源码只落在本机、没入库，于是协作者/CI 全新 clone 直接：

```
mods\zz_mods_gen.go:9:2: package dfolan/mods/odyssey.hardcore is not in std
```

启动器编译前会重算所以实机不受影响，但 `go build ./...`、`go test ./...`、
`server/Build-Server.ps1` 会撞墙 —— 这正是"仓库形态必须干净"的全部理由。

**我装了 mod 之后该怎么做。**

- 装/卸都用启动器（mod 管理器 / `modkit install|uninstall`），让它去改**本机**这份；
  改完重新编译服务端，新二进制才会带上该 mod。
- **不要把本机那份 `zz_mods_gen.go` 提交/推上去** —— 它记的是你这台机器装了什么。
  提交前用 `git diff -- server/work/dfo-lan/mods/zz_mods_gen.go` 看一眼：出现在 diff
  里的 import 若是你本机专属，就把它还原成干净形态再提交。
- 真的要把某个 mod 分享给协作者：把它的**源码**一起入库
  （`server/work/dfo-lan/mods/<mod-id>/` 整体提交，`git ls-files
  server/work/dfo-lan/mods/<mod-id>` 要有结果），加载器里的 import 才站得住。
- 判据一句话：**只有 git 跟踪的 mod 才允许出现在这个加载器里**。

**防再犯门禁。** `server/Build-Server.ps1` 编译前会机械扫一遍加载器里的
`dfolan/mods/<id>` import，逐个用 `git ls-files` 核对是否已入库：有未入库的就**报错并
中止编译**（错误信息写明哪个 mod、为什么不行、两条出路）；在没有 git 的解包目录里只告警
不阻断。本机确实要带着已装 mod 编译（不提交）时，加 `-SkipModGenGate` 跳过这道门禁。

**自证挂在哪。** `zz_mods_test.go` 带 `modtest` 构建标签，只在装了 mod 之后才有意义
（干净树上 `RegisterMods()` 什么都不注册，那些断言必然失败 —— 那是正确行为）：
`go test -tags modtest ./mods/ -count=1 -v`。
