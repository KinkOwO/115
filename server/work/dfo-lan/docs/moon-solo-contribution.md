# 沉月湖单人流程贡献补丁

## 状态与适用范围

代码基线：公开仓库提交 `8f46c8f5f468496cb022306b8908bc686f44a982`。
这是**单人完整业务链的移植候选**，不是“公开仓库旧客户端已实机验收”版本。
原实现协议证据来自 2.38.3.25；公开仓库原配套 2.38.2.34。
本次只验证代码、源数据路线和编码，不启动游戏、不替换客户端。
不能把版本只差一小版当作兼容证明，因此功能默认关闭，配置必须显式声明 2.38.3.25。
旧客户端需要维护者核验下述读包点之后再增加配置档；不要直接删除版本检查。

本补丁不含客户端补丁/DLL、密钥、官方流量、账号、玩家存档、PVF、
数据库目录、构建二进制或捐赠者的本地启动配置；遵循上游 GPL-3.0。
未开启功能时，原有普通副本/军团/账号规则保持原入口。

已接线：

1. 选定月湖频道的登录 online type 101、单人队伍模式 27/route 41；
   综合奖励测试次数通知、建队与离队。
2. NPC 开始 C2284 → 三秒准备 → 一层入场；准备期取消、加载超时撤退。
3. 源地图普通怪、两个主题特殊怪、分值门槛守门怪。
4. 守门怪死亡后等待洞口 C2062，保持同一 run/怪物编号空间进入二层。
5. 二层路线、携带未清普通怪、特殊怪逃逸报告、fever、最终 Boss 死亡通关。
6. C46 确认自己的终局 → 固定奖励计划 → 短延迟结果 → 翻牌 → 原子发奖 → 回城。
7. 未领取计划重登补领；满包不吞奖励；撤退不伪造通关。
8. 回城 own actor 基础/属性/城镇状态与穿戴恢复（NPC 修正候选，尚无公开端实机验收）。

不包含：多人邀请/中继/共享副本、官服周次数与材料扣除、官服智能掉落概率、
职业保底、装备注入高级随机属性、重启后恢复正在进行的副本。
本地免费 15 次复活、名望倍率和全服其他功能没有迁入。

## 应用与回退

先在公开仓库干净分支操作，不在有未提交改动的工作区强套：

```powershell
git switch -c contribution/moon-solo 8f46c8f5f468496cb022306b8908bc686f44a982
git apply --check <补丁绝对路径>
git apply <补丁绝对路径>
```

在仓库根执行。提供的 .diff 与 .patch 是同一份普通 Git unified diff，
二选一应用，不要各应用一次；不是需要 `git am` 的邮件格式。
若维护者上游已前移，先检查冲突，尤其 main.go、world_flow.go、session.go。
没有使用任何捐赠者主分支整体替换。回退用新提交的 `git revert`；
关闭环境变量只能停用入口，不能删除已发资产或 character_events 奖励收据。

## 配置与启动

在模块 `server/work/dfo-lan` 编译：

```powershell
go build -o bin/wireprobe-moon-solo-candidate.exe ./cmd/wireprobe
```

沿用原网关的完整启动参数、登录 fixture、数据库配置与客户端启动方式，
仅选用候选二进制，并增加：

```text
-moon-solo-config <独立配置JSON>
```

也可设置 `DFO_MOON_SOLO_CONFIG` 为该 JSON 的绝对路径。原默认归档 exe
不认识此功能；只设置环境变量却仍运行归档 exe 不会生效。
不新增端口、不代替操作者启动游戏，也不自动停止已有服务。

配置形状（占位符必须换成操作者自己的同源值；此段不是可直接启用的假数据）：

```json
{
  "client_profile": "2.38.3.25",
  "channel": 5,
  "test_remaining": 255,
  "entry": {"Town": 215, "Area": 1, "X": 0, "Y": 0},
  "rewards": {
    "Source": "<本套源数据的64位checksum>",
    "Draws": 1,
    "Choices": [
      {"Template": 0, "Count": 1, "Weight": 80},
      {"Template": 0, "Count": 1, "Weight": 20}
    ]
  }
}
```

- `channel` 是频道 ID，不是 online type。对应频道必须已在
  `-channel-refresh-config` 的 Channels 中，Type=101；
  Area、SourceValues 以及频道脚本地下城列表从自己版本 PVF 的月湖频道行提取，
  不把其它频道的十一项标量照抄过来。不存在或类型不符会启动失败。
- `entry` 的 X/Y 必须选本版本 world 导出 215/1 的可行走坐标；
  示例 0/0 不承诺合法，启动会检查。实际开始地点是 215/2。
  该配置档重选角色时只将非 215 的城镇位置投影到指定入口；
  角色走动仍沿用上游世界位置存储。请使用专用测试角色/存档备份。
- `test_remaining` 是显式测试规则，不是可消耗的官服周账；
  不以每次刷新通知“赠送”复活币。复活 UI 取上游实际 coin 余额。
- 奖励仅接受可解析的普通装备或有明确背包类别的堆叠物品。
  Template=0 必须替换。维护者从本版本沉月湖奖池选择模板，按需配置权重。
  80/20 是两项权重之比；若每种稀有度列出多个模板，必须自行均分该组权重，
  不能给每件太初都填 80 后仍声称“太初总概率 80%”。
  本候选校验模板与存储源，但**不自动证明模板属于官服月湖池**；
  奖池选择与概率是公开、独立的运营策略，不冒充官服规则。
- 不自动按职业过滤，不包含其他项目的高级随机装备生成器；
  普通装备实例值从 0 建立，耐久取装备源，实例值绝不能当发放件数。

资源前提：

- `-dungeon-catalog` 必须含 100004136 / 100004137、其全部迷宫与地图。
  仓库已有完整导出可用于离线路线测试；只含普通图的精简表不够。
- world/character/inventory/equipment/loot 的源哈希保持一致。
- 普通怪约等级 145；掉落源不仅要有高等级物品，还要含概率/金币/品级表行。
  不能再拿 level20 示例当完整掉落源。
  上游 `go run ./cmd/lootimport -source <同源inner.pvf> -max-grade 150 -output <独立loot.json>`
  可重建；再把该文件传给网关的 `-loot-catalog`。
- 上游 `cmd/dungeonfull` 带其固定源 checksum，不能拿它的固定校验套任意新版PVF，
  更不能只修改 JSON 的 checksum 来绕过源一致性。先用对应版本的导出工具。
- 源数据不足应在开始前拒绝，不通过删掉校验来让第二房清怪时断线。
- 启动需启用原完整角色/世界/装备/库存服务和基础/属性入城发送。
  本补丁不重做原登录初始化，不替换所有普通频道数据。

## 奖励与数据库边界

复用上游 PostgreSQL `CommitCharacterEvent`，不增加另一套资产表：

- `moon-clear:<run>` 固定随机结果、源、策略摘要、账号/角色及完整奖励表示。
- `moon-grant:<run>` 与全份背包变更同一事务提交；重复领取读已有收据。
- 满包整笔不发，clear 保留、grant 不落；允许回城，下次该角色登录月湖配置档重试。
  只识别两条上游容量错误，不把损坏源或数据库故障冒充满包。
- 回城/重登不改变该轮奖品，不按后来改过的概率重新抽。
- 源版本变化时旧奖品不会被强行投到另一套资产源，必须做正规迁移。
- 副本断线后不恢复战斗。仅**已收到合法 C46 并持久化**的奖励计划可恢复；
  Boss 死亡至 C46 提交之间若进程中断，目前没有持久化战斗恢复账。

这次自动检查包含纯背包的整笔失败/未知字段保留。新的 PostgreSQL 奖励链
还需要维护者在独立库验证重复请求、并发、提交后断线及重开库；
不能把“复用已有事务方法”写成这些实测已经做过。

## 最小验收顺序

开发时只跑 Moon 定向测试；交付出口再各跑一次全量 test / vet：

```powershell
go test ./internal/dungeon ./internal/loot ./cmd/wireprobe -run Moon -count=1
$env:MOON_TEST_DUNGEONS = (Resolve-Path configs/dungeons.full.json).Path
go test ./internal/dungeon -run TestMoonSoloSourceLifecycle -count=1
go test ./...
go vet ./...
```

未设置 MOON_TEST_DUNGEONS 时真实源路线测试会显式 SKIP，不算源验证通过。
原仓库不少数据库测试需要额外环境，本轮未把 SKIP 说成数据库验收。

人工一次通关：进频道→创建→NPC 开始→三秒→一层两个主题怪和守门怪→
靠近洞口→二层带怪换房、跳落/右门、特殊怪→最终 Boss→结果→翻牌物品→
回城点 NPC→再开一次→撤退。然后补满包与重登。
原公开客户端 2.38.2.34、未完成 NPC 回城实测、实际抽得的装备属性/显示，
均是合并到默认发布档之前的门，不用连续重启玩家主客户端代替版本核验。

多人迁移和协议坑见 [moon-solo-pitfalls.md](moon-solo-pitfalls.md)。
