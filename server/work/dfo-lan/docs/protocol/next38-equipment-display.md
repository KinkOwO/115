## 一、本轮核心：装备显示（已修复 + 线上验证）

### 现象
进城后身上和装备栏看不到已穿戴装备；退出重进等于"脱下"；装备属性没生效、需要武器的主动技能变灰（"打不过"）。

### 走过的弯路（已废弃）
先尝试在入城角色包（USERINFO，NOTI 类型0/ID2）的"已穿戴外观"段（客户端函数 `0x145639840`）里填入穿戴装备。

- 该段格式已逐字节对照反汇编还原：`u8 数量`，其后每条 **31 字节**（槽位 u8 + 模板 u32 + 13 未知字节 + 3×u32 + 1×u8）。
- 槽位就是客户端装备枚举：`12=武器, 13=称号, 14=上衣 … 19=项链 … 25=耳环`，与 NOTI13 穿戴列表同一套编号（枚举注册在 `1470CB2A0`，1 基）。
- 角色列表（roster）行解析用的是同一个 `0x145639840`，格式一致。

→ 据此部署 **dungeon38** 后，客户端进城**崩溃**。

### 崩溃定位（隔离客户端 exception-trace 抓取）
- 访问违规 `0xC0000005`，出错指令在 u32 读取器 `0x146ea0ba0`（RVA `0x6ea0bb0`，`mov eax,[rdx]`，rdx 为非法指针 `0x7FE90000`）。
- 调用来自角色包最后一个"集合"解析 `0x14563c140`：它先读一个 u32 数量再按数量循环读对；崩溃时循环下标已到约 43.9 万（`RBX=0x6B5EB`）——**数量被读成了天文数字**。
- 结论：往自己角色的外观段填真实装备会让解析游标错位，后续字段全部错位，最后那个集合的数量读成垃圾 → 指针冲出缓冲区。**"自己角色走外观段"这条路彻底废弃。**
- 旁证：能玩的 dungeon37（外观段为空）与崩溃的 dungeon38 唯一差别就是这段；两者日志里缺失的弓手资源一模一样，dungeon37 不崩，所以问题在这段数据、不在客户端/存档。

### 正确修法（dungeon39）
自己角色的装备改走**玩家"当场穿装备"本来就用的通道**：NOTI14 装备槽刷新（`InventorySpaceUpdate`，list3），在入城序列**末尾（进城之后）**把穿戴装备补发一遍。这条通道客户端接受、不崩、且会触发外观重建。

- NOTI13 list3（`WornRestore`，入城已发）只填"穿戴数据页"，**不重建外观**；NOTI14 才触发外观重建——这就是之前退出重进"脱下"的根因。

### 验证
- 隔离客户端 exception-trace 自测：进城近 1 分钟无访问违规、进程存活。
- 用户线上确认："正常显示了，退出重进也在。"

- 装备外观段 `0x145639840`：格式已还原（31 字节/条），但**自己角色不能用它**（会崩）。序列化器保留在 `protocol.EquipmentAppearance`（已测），但 `UserInfoBasicProbe` 默认拦截装备、发空段（安全）。若日后要做远端玩家外观，可从这里接续，但需先解决那几个未知字段。

- 记住：NOTI13 list3 只填数据、NOTI14 才重建外观。
