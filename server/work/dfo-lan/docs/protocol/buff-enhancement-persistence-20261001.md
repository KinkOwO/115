# Buff Enhancement 登记保存与恢复

## 问题与原因

原服务端未逐次处理Buff登记请求，登记无法在重新选择角色或重启游戏后可靠恢复。登录持久化之外，进入地下城和回城会重建角色；客户端USERINFO换装段清空按actor绑定的登记集合，导致进图Buff无登记增益、回城登记UI清空。

修复通过服务端保存登记，并在登录、进图及回城的角色和装备对象更新完成后恢复完整集合。客户端按照登记装备计算Buff效果，本改动不修改伤害公式。

## 协议与恢复顺序

布局以当前115级客户端sender/reader为依据，沿用既有wire codec。

| 报文 | 正文与用途 |
|---|---|
| CMD1421 | `skill:u16 LE, kind:u8, list:u8, slot:u16 LE`；正文6字节，兼容实机末尾2个零填充。 |
| 技能选择/取消 | `kind=48, list=46, slot=FFFF`选择skill；skill0取消选择。装备kind与同一空位置组合解除该项登记。 |
| NOTI1361 | `skill:u16 LE, count:u8`，随后每项`exists:u8, kind:u8, list:u8, slot:u16 LE`；客户端先清缓存，再通过NOTI1360 reader绑定当前物品对象。 |
| CMD1421回执 | 成功回执后恢复完整登记；失败先回滚客户端乐观编辑，再恢复权威集合。 |

登录恢复放在技能、背包、穿戴、时装和宠物等数据更新之后。进图加载完成和回城在最后的角色/装备更新后追加NOTI1361，覆盖重复加载及死亡返回；防止先绑定旧对象后又被USERINFO清空。

对应客户端函数已记录在`analysis/dumps/idb_funcs.tsv`：CMD1421 sender `1436436D0`、结果处理`14363DF50`、NOTI1360/1361 reader `14363E4B0`/`14363EED0`、USERINFO换装段`14563C1F0`、actor登记清理/复制`143642610`/`143643910`。

## 保存与校验

- CMD1421每次编辑均解析，不受请求采样次数限制；校验checksum、选中角色、已学技能、物品归属及装备目录源种类。
- 在角色JSON增加可选`buff_enhancement`：version、skill和登记items(kind/template/fingerprint)。复用`CommitCharacterEvent`角色锁与receipt事务，保留其他存档字段，无表结构变更。
- 会话nonce与递增序列生成事务键，避免选择A→B→A被错误当成重复。失败不扣物或落成功登记，登记不改变背包。
- 物品指纹忽略Slot与Record中的位置字段，恢复时在拥有的背包/穿戴/特殊容器中寻找唯一匹配，避免移位后丢失或槽位复用误绑。
- 旧存档缺登记字段按空集合恢复，清除前角色缓存。损坏可选登记在登录时清客户端缓存并记录错误，不阻止入场、不重写原存档。

## 回归验证

训练场验证了不同Buff倍率下登记后的等级与增伤、取消登记后的增益回退。登记在重新选择角色、重启、进图与回城后保留。伤害观察与提示倍率在整数显示精度下相符，不作为完整精确战斗公式证明。

自动检查分为三类：协议测试使用原生报文字节验证请求字段与NOTI1361构造，并拒绝错误长度、非零填充和非法引用；角色测试覆盖旧存档、其他字段保留、技能切换、取消登记、移动和重复实例；场景测试确保物品/技能更新先于恢复，并覆盖重复加载、回城和Clone装备更新顺序。

`testdata/native_buff_enhancement.json`仅作为测试固定向量，不是运行配置或玩家存档，服务端运行时不读取。原生离线提取中的库存/actor/UI/效果调用使用stub，向量只证明协议字节与构包，不证明真实战斗效果。

数据库专项测试需显式设置`BUFF_INTEGRATION_CONFIG`，在独立临时schema中检查事务保存、独立连接读回、receipt重放、清空、越权拒绝及其他字段保留；未配置时默认跳过。全量`go test ./...`与`go vet ./...`用于代码回归。

## 当前边界

指纹包含耐久、锻造、时装选项及其他物品内容；这些字段改变后需重新登记。同指纹重复实例不自动选择，尚未引入稳定全局实例ID。全部物品类别、强化/附魔/修理/出售/过期等生命周期及精确完整伤害公式未扩大为已验收。

没有修改客户端/DLL、运行资源、wire codec或数据库表结构；旧程序可忽略新增可选存档字段。
