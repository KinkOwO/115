# 第 25 版候选：90CN 参考适配

状态：代码与本地验证候选，未切换真实客户端。当前源码 `dfolan` 保持独立，参考包模块 `longheng.io/server` 没有作为依赖执行。

参考原件及提取清单见 `../../../dnf90_reference/README.md`。当前 PVF 校验值为 `7ef2db59331f7e5b18b2f250b8b907526bf2c94b17a7312036cf599644d88e80`。

## 代码改动

1. **初始技能**：只解析各职业技能元数据的首个 `[type]`，避免把后续攻击段的 `[type]` 当成主动技能类型。按当前 .chr 的初始技能给角色；Slayer 快捷栏为 169/46/5，Knight 修正技能索引路径。技能树保留当前 protobuf 必填字段。
2. **房间与小地图**：进入副本时发送当前角色的 dungeon 状态，解除原生下一房间请求的状态门槛；小地图 BOSS 坐标与随机深渊坐标分开。使用原 PVF 的五房间路线，保持怪物源索引及唯一场景编号；非战斗剧情对象不会堵普通房间的门。
3. **任务进度与提交**：源地图完成后更新剩余目标数；3145 的完成依赖真实 BOSS 确认流程。任务状态、经验、等级成长、SP 和完成凭据同一事务提交。重复提交不再次发送可能访问已删除任务对象的终结 ACK。重登恢复已完成任务集合。
4. **经验与通关**：导入当前怪物经验、等级阈值、SP、基础职业成长、任务参数和评分阈值。参考公式和倍率放在独立兼容配置中。怪物、任务、通关使用不同幂等事件键；评分与通关结果按当前原生格式编码。
5. **金币与普通堆叠物品**：导入当前金币表、概率表、等级/稀有度表和 1,022 个低等级堆叠物品定义。每个房间保存自己的随机数状态，同一怪物不会重新抽奖。掉落和后续房间的怪物共用场景编号分配器。拾取核对账号、角色、场景、物品归属与请求距离，再原子保存背包和凭据；成功后发送当前金币/普通物品各自的回包。
6. **背包恢复**：恢复当前 list0 的完整背包，避免切角色沿用上个角色的物品。未知角色 JSON 字段与已有经验不会被背包更新覆盖。拾取拒绝带上当前协议要求的场景物品编号。

所有模拟均读取原 EXE 指令，在私有 Unicorn 内执行，游戏/UI/网络调用替换为受控桩；不等于真实客户端验收。

| 证据工具（`../dfo_probe_tools/`） | 验证内容 |

| `boss_check_oracle.py` | CMD117 的 12 字节请求、NOTI115 的 BOSS 确认 |
| `progression_packet_oracle.py` | NOTI37 的 82 字节格式及大于 32 位的角色经验 |

| `drop_item_oracle.py` | 当前金币/普通物品的 193 字节场景记录 |

## 验证范围

- `go test ./...` 与 `go vet ./...`。
- `go run ./cmd/charactercheck` 只使用临时 schema：12 路并发重复经验、通关、任务提交和拾取都只有一次实际入账；验证跨账号拒绝、未完成拒绝、错误房间拒绝、重开连接、事务回滚和缓存失效。
- 数据库检查中：怪物经验 104；3145 任务经验 1,200；等级 3 副本参考结算基础 163、评分加成 24；金币 34 与一件当前源投掷物保存后可以恢复。这些是明确输入下的验证样例，不是所有等级统一奖励。
- 保留第 24 版二进制，未迁移用户角色数据、未运行参考包 SQL、未重启游戏客户端。

## 尚未完成

- 90CN 也是兼容实现。原版服务器的完整概率、最终倍率和私有结算规则仍不能从此包直接断言。
- 当前装备字典生成权重未确认，候选不会制造装备掉落；命中未支持的装备分支会记录 `drop_rules_pending`。独立、世界和指定怪物物品池未接入。
- 当前物品投影只导入 grade≤20；运行时限制在已完整覆盖候选等级区间。只有金币和源堆叠物品可拾取，装备、物品使用、移动、交易仍待各自协议实现。
- 按职业筛选后存在实际物品奖励的任务仍拒绝提交，不会把任务标完成却吞奖励。后续 3146 剧情目标、可接任务图标、新手关卡完整链路仍未完成。
- 普通副本翻牌是 CMD69/70/71/72 阶段，已找到参考实现；当前第 25 版未实现完整翻牌奖励或依靠伪造空奖励放行。
- 怪物死亡仍采用客户端死亡报告与服务端场景归属校验，尚不是完整的服务端伤害/血量裁决。
- 真实客户端尚未验证候选版本的技能图标、施放/行走动画、实际血量与战斗、五房间移动、拾取表现、任务提交和通关退出。当前地图已加载与本地测试通过不能替代这些验证。
- 正式登录器、独立账号绑定与 LAN 多客户端互见仍是独立的后续验收项。

上述事项未完成前，不把该候选称为“全部修复版”，也不要求用户反复逐项试验。
