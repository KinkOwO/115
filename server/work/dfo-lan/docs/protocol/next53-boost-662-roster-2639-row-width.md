## 结论

旧 donor 布局把 2639 的行宽写成 5 字节（`{u32 槽位, u8 模式}`）。行宽错 2 字节：

- 1 行：客户端需要 11 字节，正文补齐后 16 字节 ⇒ 收下（第一个角色一切正常，纯属侥幸）；
- 2 行：客户端需要 18 字节，正文只有 16 字节 ⇒ 游标越界 → CMD217 → 该帧之后 662 的
  名单/训练状态不再被客户端采纳（第二个角色停在赛利亚），选角名单渲染为空。

## 改动

`protocol.BoostRoster115` 改为客户端原生行宽：`u32 行数` + 每行 `{u8 轨道=3, u32 名单位次, u8 状态, u8 保留=0}`，
并导出 `BoostRosterRowBytes115 = 7`。轨道/保留取自官服帧观测值。调用方
（`boostRosterForRoles` / `selectionRosterPackets` / `boostLoginRoster` / 胶囊计划）不变，
仍按同一次名单快照给位次、`Finished → 2`。

新增 `TestBoostRosterRowWidth115` 钉住三种正文的逐字节值与 `4+7N` 长度契约。
