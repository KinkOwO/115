### 三个发送方的入口都拿不到（三条负证据，各有阳性对照）

`0x146d494b7`（CMD132）、`0x145bec591`（CMD623）、`0x145bec78b`（CMD35）：

⇒ 静态三条路都排除，入口只能是 VMProtect 段内的派发或运行期构造的表；这一条只能靠 IDB 或活体探针。

### 1. 机制：`opcode % 14 → 密码槽 → alignment`

- 服务端镜像 `internal/game/wire/cipher.go`：`packetCipher(keys, id)` 用 `index = id % 14` 选 14 个槽之一，
  每槽自带 `alignment` ∈ {4, 8, 16}；`DecryptPayload` 对 `len(payload) % align != 0` 直接
  `invalid encrypted payload alignment` 报错；`EncryptPayload` 先
  `plain := make([]byte, (len(payload)+align-1)/align*align)` 再逐块加密 ⇒ 尾部补的是**零**。
- 实机核对（本机唯一存活会话 `runtime/roles_persist_…_20261012_140432_548940_next37/events.jsonl`：
  `kind:"client_frame"` 共 **175** 行，其中 **55** 行带非空 `plain_hex`、9 行带空串、111 行无该字段；
  本轮按 34 个不同 opcode 逐条判 `len(body) % align(id)`，带明文的 55 条**全为 0，违例 0 条**）。
  （55 条覆盖 34 个 opcode；9 条空体也全是 0。）
