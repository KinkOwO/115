# 旧装扮礼包开箱修复及兼容性审查

## 问题与修改

旧装扮礼包 `50041807`、`590700394`、`590701513` 的 `[avatar]` 原始奖励记录为
`1, (template, weight, count, 1, 0)...`。原 reader 先过滤零，导致记录无法按现有三元组解析，
开箱返回 `has no reward pool defined`，客户端将拒绝显示为“物品栏空间不足”。
此提示也可能有其他原因，本修复不把所有空间不足都归为同一问题。

修复链：PVF `[booster info]/[avatar]` → `parseFixedAvatarPool` → 现有奖励池及抽取执行 →
原子开箱事务 → 原有角色存档与 CMD160 应答。

- 在过滤零之前识别已确认的 `1/0` 尾字段；奖励模板、数量、权重全部来自同一内层 PVF。
- 只有首条记录具有该尾字段时才进入新分支，避免把五候选普通三元组误认成扩展格式。
- 未支持的独立 `30/0` 等格式沿用旧 reader，不阻断混合礼包已经支持的其他奖励。
  已识别的新格式内部存在非法数量、权重、尾字段或缺失结束标记时，拒绝整个奖励集合，避免半套发奖。
- 奖励路径含 `avatar` 时，只有装备类型按装扮发放；皮肤选择礼盒等 stackable 保留普通物品归属。
- 开箱 NOTI14 装扮通知仅序列化新增/改变的槽位。完整背包仍落账保存，未改变的旧物品不会删除或迁移。

旧存档可能已把皮肤选择盒 `590701702` 存入装扮容器。重发这种旧条目时，当前客户端 reader
`145A83FA0` 不按实际装扮读取期限，导致后续字段错位。本次避免重发未变条目，
不声称修复全部旧存档错误，也不改变登录背包投影。

证据会话：`roles_persist_select_actor_town_world_live_detail_dungeon_manual_20261008_230633_967028_next37`
记录奖励池缺失；`roles_persist_select_actor_town_world_live_detail_dungeon_manual_20261008_233337_561265_next37`
记录第一次八件发放及旧背包通知问题。测试副本的角色隔离、客户端 PVF 预览、DLL 分类和 MOD 安装均不属于本次提交。

## 礼包与商城影响范围

修改没有进入商城商品列表、分类、价格、职业显示、购买扣款、购买发货、协议 opcode 或数据库 schema。
普通装备、宠物、称号、契约、选择箱、空奖励占位符仍走原有分支。
真实旧礼包中原来解析为空或错误的已确认装扮记录会产生正确奖励；这是有意改变，不应声称所有礼包内容逐字不变。

审查发现并修正两处候选问题：五候选普通三元组误判；遇到未知旧装扮格式时误拒绝同礼包的其他已支持奖励。
对应新增兼容性回归测试。开箱测试验证消耗礼盒、奖励入库、既有装扮/无关角色字段保留、
ACK 内容及装扮增量只包含本次新增条目。
