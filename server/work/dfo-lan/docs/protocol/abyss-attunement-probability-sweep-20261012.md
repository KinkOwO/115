# 大深渊「调律之边界」概率核对：事件分支掷骰 + 命运的凝械触发门（2026-10-12）

范围就是业主那两句话：「帮我弄 100W 个种子看看事件触发概率」，以及追问
「命运的凝械触发也没有问题吧 / 不是服务器下发的事件吗」。第二句**业主是对的**，
本文按两层分别核对，并纠正两条我自己记错的归属。

代码侧本轮**没有改动任何运行路径**：新增的只有一个分发测试（§4）。

## 1. 两层概率，各自走生产入口

| 层 | 入口 | 谁调它 |
| --- | --- | --- |
| 珠子线（fixed）/ 天平线（additional 分支） | `loot.AttunementRewards.PlanRun` → `RollPlanned` | `cmd/wireprobe/oath_info.go` 进本时掷，掉落阶段照计划付 |
| **命运的凝械的触发门** | `dungeon.chooseMaze` → `randomUint64()%total` → `pickWeightedMaze` | 进本选图。`[hidden drop table]` 只挂在 epic.ctp 的 **maze 1/2**，所以这一掷就是那场事件的开关 |

第一层此前已有百万级核对；第二层**从来没有分发测试** —— `maze_choice_test.go` 只钉边界与
回退（哪一段落在哪一张、权重不齐时退回最小 index），一次都没量过比例。本轮补的就是第二层。

## 2. 事件分支：132 个位次 × 1200 万场

12 个 (副本, maze) 组合各 100 万场：**最大偏离 0.0187 pp（0.57σ）**，零条不可达分支，
**实付 ≠ 计划 0 场**。逐支明细见随包件 `深渊事件概率-100W种子逐支明细.txt/.json`。

与命运的凝械直接相关的那一支：epic.ctp 位次 8 / `eff 305` 神兵认主，条目就是武器载体
`10409487`(史诗) / `10409488`(太初) —— 源 2.0000% → 实测 2.0037%（0.26σ）。

两条判据（写探针时踩到，避免重复）：

1. **不能按 `[effect index]` 聚合**。`eff 1001` 在 epic.ctp 占三个位次（虚无之魂 ×5/×10/×15），
   按 index 合并会把源 18% 读成 6%，报出一个根本不存在的 −12 pp 偏差。两边都按位次求和。
2. **计划 vs 实付要按位次比，不能数同一模板出现几次**。`unique.ctp`（100005066）把
   `10419721..24` 四件**同时**写进 fixed 池和 additional 位次 3 ⇒ 一次合法通关同件付两次
   （珠子线一次、天平线一次）。按出现次数比会误报「planned x1 / paid 2」。
   `RollPlanned` 的顺序是 primer 先、oath 后，所以判据是 `len(awards)-OathAmount` 那段切片。

## 3. 触发门：100005068 确实按源掷

`internal/dungeon/maze_chance_distribution_test.go`，100 万次真 `chooseMaze`
（输出即随包的 `触发门-100万次选图实测.txt`；这条线用 `crypto/rand`，**每次跑数字都会变**，
本文与证据文件是同一次运行）：

```
epic 砝码大深渊 100005068：源 [990000 9143 857]
  maze 0   99.0000% →  99.0104%   +0.0104 pp  (+1.05σ)
  maze 1    0.9143% →   0.9044%   −0.0099 pp  (−1.04σ)   ← 命运的凝械·史诗
  maze 2    0.0857% →   0.0852%   −0.0005 pp  (−0.17σ)   ← 命运的凝械·太初
小深渊 100005014（服主改过权重 [980000 20000]，源是 992857/7143）
  maze 0   98.0000% →  97.9903%   −0.0097 pp  (−0.69σ)
  maze 1    2.0000% →   2.0097%   +0.0097 pp  (+0.69σ)
```

零张不可达，最宽 1.05σ。判据三条：权重非零却零命中 ⇒ 红；偏差 >5σ ⇒ 红；绝对偏差 >0.5 pp ⇒ 红。
必须换算成 σ 而不是只看绝对值：1e6 次对 2% 那一档的 1σ 就是 0.014 pp，对 0.0857% 那一档是 0.0029 pp。

另有一道**必查的前置事实**：`chooseMaze` 只把「同 quest 且无 `Pending`」的 maze 送进掷骰，
所以权重对不代表掷得到。实测 100005068 三张 maze 全是 `quest=0`、`Pending` 为空 ⇒ 真进候选
（见随包 `迷宫门-源与白名单比对.txt`）。

## 4. 待业主裁决的一处不一致

`configs/pvf-scene-policy.json` 的 `maze_rates` 是**白名单**：源里有 67 张副本声明
`[maze chance rate]`，只有列进来的才启用掷骰，其余保持「同 quest 取最小 index」的旧行为
（取舍写在 `internal/catalog/maze_chance.go` 注释里：加一张副本 = 加一行策略，不做全局行为变更）。
当前只列 100005014 与 100005068。

`100004768`（`fortifieddiscipleofdoom/epic`）：

- 源里声明**同一组**权重 `[990000 9143 857]`，三张 maze 同样 `quest=0`、无 `Pending`；
- 自己的 ctp 里带**同样的 50 格 hidden 表**（maze 1 index0×1 / 1×12 / 2×12 / 3×12
  ＋ maze 2 index0×1 / 2×12，与 100005068 逐格同形状）；
- 但不在白名单里 ⇒ 运行期不掷图，永远进 maze 0 ⇒ **那一场副本里命运的凝械一次都不会触发**。

这不是掷错，是白名单没打开。只挑 5014/5068 是有意为之，4768 属遗漏还是故意不做，
源里没有证据可判 —— 需要业主口径。本轮**没有**擅自改策略文件。

## 5. 归属订正：命运的凝械「给哪一件」不是服务端掷的

`990000/9143/857` 属于 `[maze chance rate]`，**不属于** `[hidden drop table]`。
复验源结构：hidden 每条只有 `tier / key / item` 三个字段，**没有任何权重列**；
48 张组（21384~21431）组内**等权重 20**、`creation_rate=[0,0]`、无 `[target]`。

所以这条链上的随机只有两处：

1. 玩家 CMD2406 选定格子 → 载体（源口径，不掷）；
2. 载体展开到组内哪一件 → 组内等权重（源口径）。武器格多两层：`[etc] 1` 两条各 500000
   掷「普通/传承」（源权重，真掷），再按职业筛后等概率取一件 —— 后者是**服主 policy**
   （业主口径「就按鬼剑士系 掉一把」），不是源口径。

实机两条样本可对上账：16:41:10 与 16:42:05 同一角色，筛剩都是 5 件、候选整组 id 位移 3
（= 普通/传承掷到不同组），发出的是 `101021076` 与 `101031192`（= 筛后等概率确实在变）。
