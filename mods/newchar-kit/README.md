# newchar.kit —— 新角色出厂补给

新角色**创建提交成功后**发一套出厂补给。纯 Lua 奖励规则脚本：**没有 Go 代码**，
装的时候不建源码目录、不写 mod 加载器、也不跑编译 —— 脚本落到
**`<启动器根>\mods\newchar_kit.lua`**（**平铺**，与各个 mod 库目录同级），**重启服务端即生效**。

## 当前形态：一个脚本（业主原稿）

| 脚本 | 内容 |
| --- | --- |
| `server/rules/newchar_kit.lua` | 业主提供的 `newchar_kit.lua` 当前版（**sha256 `cba54ad3…`**，22,175 字节）。金币 3 亿 + 点券 50 万 + 背包可堆叠物 16 类走 `grant_item`；其余（通用毕业装备 23 件 / 宝珠套 / 宠物装备 / 职业套装 12 件 / 毕业武器）走 `send_mail`；有 `ctx.profession` + `ctx.advancement` 时按职业判输出/辅助，拿不到就只发通用那部分。整个文件只有**一处** `on("character_create", …)` |

`mod.json` 的 `layers.server.scripts` **只声明这一项**（`server/rules/newchar_kit.lua`）。

> **两份别混**：`variants/original/newchar_kit.lua`（20,364 字节，sha256 `66e6236e…`）
> 是业主**原稿的逐字节留档**，**不参与安装**；它和当前脚本**内容不同**。
> 旧文把 `66e6236e…` 当成"当前脚本的哈希"、把本 mod 说成"两个脚本"都不对
> （哈希请用 `Get-FileHash -Algorithm SHA256` 现算，别抄文档）。

## 另一份：按"两层两个脚本"拆过的版本（备用，不参与安装）

[`variants/two-layer/`](variants/two-layer/) 里是按你先前口径拆开的两个独立脚本
（`newchar-general.lua` 通用层 / `newchar-class.lua` 职业层）。它们**不在** `mod.json` 的
`server.scripts` 里，也不进 zip，所以不会被装上；要启用就把 `mod.json` 的 `scripts`
换成它们（或另存一份 mod）。

## 内容真源与服务端能力（2026-10-06 定调）

**能不能发是服务端能力，发什么由 mod 的脚本决定。** 服务端为两条通道提供的能力：

| 通道 | 服务端保证 | 不在时会怎样 |
| --- | --- | --- |
| `grant_item(id, n)` | `id 0` = 角色金币；**是堆叠物就按堆叠发，否则按装备发并实例化**（宠物装备落宠物装备栏）。**一次调用是一整批**：一个号不合格，整批（连金币）都不发 | 报错**点名模板号**（`模板 <N> …`） |
| `send_mail(..., 附件)` | 同一套分流：是堆叠物按堆叠发；否则按**装备**发 —— 只要 **PVF 里有这件装备的定义**（`<id>.equ`，**不必在掉落池/奖励选集里**），服务端就能取到耐久与部位并实例化 | 同上，报错带号 |

> 旧口径（2026-10-06 之前）：邮件装备必须先在**掉落目录**里、再在 3,174 行的**装备选集**里
> 取到耐久 —— 于是"发一件毕业装备"被**掉落表**锁死（现场报 `模板 500950043 不在奖励目录里`）；
> 而且 `grant_item` 只能发堆叠物。**这两条都已作废**：现在服务端把"PVF 里存在的装备都能取到定义"
> 这条能力交给奖励路径（`cmd/wireprobe/bootstrap.go` 给奖励目录挂上完整定义目录），
> `grant_item` 也走装备分支（`internal/inventory/awards.go:49-91`），服务端**不持有任何内容清单**。

### 本仓库这套补给里已知的一个坑（已定位）

- `100360012`（神圣符咒）在本客户端里是**装备**（`equipment/character/common/charm/100360012.equ`），
  **不是堆叠物**。它原先排在 `grant_item` 的 16 类里 → 旧口径下这**一个号**让整批
  （金币 3 亿 + 其它 15 类）一起回滚；新口径下它会按装备发出来（`grant_item` 自己就能发装备了）。
- 其余 15 类是标准堆叠物（`stackable/<组>/<id>.stk`），没问题。
- 模板号在 PVF 里根本不存在时仍会失败 —— 但现在**报错一定带模板号**，跑一次新号看日志即可逐个修正。

## 装 / 卸

- **装**：启动器「MOD 工具」页勾上本 mod → 「安装选中」；或
  `modkit install --client <客户端> --mod <本目录或 zip> --root <整合包根>`。
- **卸**：同一页「卸载选中」。**脚本不随卸载删除**（2026-10-06 业主定调）：
  `newchar_kit.lua` 留在 `<启动器根>\mods\` 变成"手工脚本"，只摘掉注册表里的条目
  —— 也就是说**卸载后它下次启动服务端照样生效**。要真停用，去「Lua 规则脚本」面板删它。
  （只有**安装失败/升级的内部回滚**才按登记哈希删脚本。）
- 这份脚本在管理页下半部分「Lua 规则脚本」可见，来源显示 `mod newchar.kit`，在那儿**只读**。

> ✅ **一个好消息（与 `odyssey.hardcore` 那类 server 层 mod 的差别）**：本 mod 是**只带
> `server.script` 的规则脚本 mod**，**不参与编译、不进 `mods/zz_mods_gen.go` 那个加载器**，
> 所以**不受"当前已发布版启动器（v1.7.7）只能同时装 1 个 server 层 mod"的限制** ——
> 它和别的 server 层 mod 可以同时存在（脚本按文件名平铺，跨 mod 同名才会被 `plan` 拦下）。
> 两段口径见 [`../MOD-DEVELOPMENT.md`](../MOD-DEVELOPMENT.md) §4.8。

## 邮件标题为什么是英文

服务端把邮件标题按 GBK 发出去，115 客户端会把中文渲染成乱码。脚本里标题统一
`Starter Kit - <项> <第几封>/<共几封>`，纯 ASCII。

## 这一层**做不到**的（仍要 Go 侧或工具补）

**已经能做了**（服务端 2026-10-06 两批"角色待遇"能力，脚本里直接调）：

| 项 | 脚本写法 |
| --- | --- |
| 穿戴位挂锁 `expand_equip_flags=59` | `unlock_equip_slots(59)`（五个扩展位全开；按位或，不会把已有的位抹掉） |
| 背包扩容档位 2 | `expand_bag(2)`（只升不降） |
| 时装栏扩容档位 15 | `expand_avatar(15)`（只升不降） |
| 复活币 100 | `grant_revive_coin(100)`（累加） |
| 个人金库 264 / 264 | `expand_vault(2, 264)`、`expand_vault(45, 264)`（8..264、步长 16，只升不降） |
| 账号金库 320 | `expand_vault(12, 320)`（8 的倍数、≤320） |
| 账号材料仓 6×10000 | `grant_account_material(3033…3037 / 3262, 10000)`（模板不在服务端映射里会被拒并点名） |
| 皮肤仓库全解锁 | `unlock_skins()`（账号级、幂等，清单由服务端按运行期皮肤目录现算） |
| 宠物本体 / 宠物用品 | `grant_pet(<[creature] 模板>)`、`grant_pet_item(<[feed]/[creature] 模板>, n)` —— **能力已就绪，但本包不知道模板号**（原数据源在另一台机器的 `newchar-kit.json` 里，本机取不到），所以脚本里留的是注释位 |

### 「皮肤仓库全解锁」要知道的四件事（都是取证结论，不是推测）

1. **`1068` 这个数字在本客户端不成立**：本仓库实测皮肤目录约 **1733 条** entry（另有 **127 条**模板的
   `[add skin storage]` 指向 `list/skin.lst` 里不存在的 ID，属审计项，**永远解锁不了**）。所以脚本里不写数字，
   由服务端按运行期目录现算。
2. **武器外观不在这张表里**：它是角色级 `Bag.WeaponSkins`，全解锁**不会**让武器外观页签变满。
3. **客户端只推它认识的那几族**：边框/觉醒插图/表情/涂鸦/飞空艇特效/伤害字体有页帧，其余族能解锁但界面看不到。
4. **「最近获得」那一栏硬上限 255**，全解锁后它只显示前 255 条（客户端限制，不是丢数据）。
