# refactor(server): 服务端依赖契约基线

## 摘要

为 `refactor/go-server-dedup-20260930` 建立**可机械判定**的服务端依赖契约，作为后续边界收敛的真源。到本 MR 为止，依赖规则只是口头约定（"只消除没有业务含义的转发"），导致 `domain -> storage`、`storage -> domain`、`protocol -> domain` 都被当作可接受现状，历次精简后依赖形状仍收敛不了。本 MR 把规则固化为文档，并把现存违例登记为**只减不增**的例外清单。完整契约见 `server/work/dfo-lan/docs/architecture-contract.md`。

## 主要内容

- 新增 `server/work/dfo-lan/docs/architecture-contract.md`：
  - 分层 L0 传输 / L1 协议与静态数据 / L2 持久化 / L3 领域 / L4 组合工具。
  - 六条依赖规则（R1 纯基础设施不得依赖领域；R2 领域不得依赖 `storage`；R3 `storage` 可实现领域接口但不得定义游戏事实；R4 领域间协作必须显式；R5 禁止依赖环；R6 组合/工具层不承载游戏规则）。
  - 22 个内部包的所有权表（拥有者 / 允许依赖 / 禁止依赖）。
  - 落位判断的唯一标准：是否知道"某个具体游戏事实"。
  - 强制机制与例外清单（= `archtest` 允许清单）的规格。
- 例外清单基线（`939c749` 时点，只减不增）：协议→领域 4 条、领域→`storage` 6 条、领域↔领域 4 组。
- 明确 `architecture-refactor-plan.md` 为历史进度记录，本文为规则真源。
- 更新 `CHANGELOG`。
