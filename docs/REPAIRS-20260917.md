1. 独立项目的提交分支为 `submit/repairs-20260917`。先检查 `git status --short` 和差异；当前任务没有执行 push 或创建远程 MR。

3. 提交前如上游又变化，先 `git fetch origin`，在提交分支执行 `git rebase origin/main`；处理冲突后重跑测试。这是准备提交时同步。
4. 管理员合并 MR 后，在这个独立仓库执行下面命令。这就是“合并 commit 后记得 pull 上游拉更新”：

```powershell
git status --short
git switch main
git pull --ff-only origin main
git log -5 --oneline
```

只有工作区干净且本地 main 没有分叉时使用上述快捷流程。`--ff-only` 遇到分叉会停止，不制造额外合并提交。若是通过 fork 工作，`origin` 在本项目仍指目标上游，`fork` 是自己的仓库；不要混淆。原运行目录没有 Git，本次不在其中执行这些命令。
