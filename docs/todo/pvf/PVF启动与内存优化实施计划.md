## 目标与基线

在全部 54 个领域仍可用、原生数据含义与准入范围不变的前提下，降低启动峰值、稳定堆占用及目录准备耗时。保留所有原生物品 ID 查询能力，不以删除冷门模板或改变存档 source 换取性能。

基线为 configs/pvf-default.json、bin/wireprobe-pvf.exe 和 7ef2db59331f7e5b18b2f250b8b907526bf2c94b17a7312036cf599644d88e80 内层归档。归档 760530763 字节、5650173 个目录条目。2026-10-01 的只读目录检查：准备 56.6165 秒、进程总计 59.42 秒、峰值工作集 8495.5 MiB、峰值私有内存 8501.7 MiB。该入口在正常启动的显式 GC 前退出，因此这些值不是游戏服稳定内存。证据位于 server/work/dfo-lan/.tmp/pvf-perf-analysis-20261001-133620/。

## 实施顺序

### 第一批：归档与解析基础设施

1. 增加源打开、领域准备、GC 后的耗时/堆指标，目录检查也输出 GC 后内存。
2. 运行源使用只读文件句柄；完整 SHA256 以流式计算验证，正文通过 ReadAt 按块读取。固定句柄贯穿查询生命周期，禁止静默重新打开另一个文件。
3. 运行目录保留原生 24 字节记录，用紧凑的路径哈希索引定位；命中后比较完整归一化路径处理碰撞，重复路径仍选原生第一项。File 字符串视图按需创建，避免 565 万条字符串/结构体同时常驻。
4. 装备子视图只保存所需记录，独立持有共享文件资源；父源关闭后装备仍能查询，最后一个使用者释放句柄。
5. 所有运行导入解压缓存按字节限制；淘汰单个旧条目，避免整表清空。大型块可读取但不进入缓存。
6. ReadScript 从同一份原始字节计算哈希和 token，取消二次读取与复制。

保持内存型 Open/OpenBytes 供既有离线工具及测试使用，不扩展客户端补丁/资源修改。第一批验收要求：全量目录准备结果等价，峰值显著下降，GC 后保留内存有数据，读取耗时不明显回退。

### 第二批：减少重复物品扫描

将原生 LIST 绑定和物品脚本扫描统一调度，复用一次解析提取期限、价格、堆叠分类、材料、皮肤与其他可合并字段。先覆盖有完整对照的简单投影，再接复杂礼盒/强化/名望逻辑。不缓存全部 token 作为长期对象；保留每个导入器原有字段顺序、覆盖规则、拒绝原因与路径回退行为。

验收：逐字段对比原有导入输出，包含无效价格、期限、材料缺失、重复 tag、别名及 (r) 回退；测量解压/解析调用次数与耗时。

### 第三批：按物品、按副本加载

建立共享查询接口与有界详情缓存。登录预热当前角色装备、背包、技能及任务依赖；副本进入前准备所需地图/脚本，交易前准备相关物品。全局列表/跨模板搜索保留必要的紧凑索引，加载失败必须显式拒绝，不返回免费价格、错误槽位或缺省奖励。验证重登、仓库、邮件、商城发货、期限、穿戴、技能、副本和开盒。

首段按堆分析处理MAP脚本：保留副本布局、地图ID/路径/哈希，启动仍读取校验各地图以保持原准入和跳过记录，但不长期保存全部MAP token。运行统一通过MapScript读取，并使用按估算字节和条目数限制的缓存；地图覆层保留原已验证脚本。进图、换房、剧情、复活和任务NPC读取共用此入口。装备原有按条查询继续保留，后续依据新的堆分析再评估物品索引、技能/任务投影及角色依赖预热。

### 第四批：可失效的磁盘派生缓存

仅缓存确定性的运行投影，绑定 PVF SHA256、解析器版本、领域及策略内容哈希。原子写入，损坏/异源/异版本拒绝并重建。缓存是可删除的性能产物，PVF 继续为真源；玩家 config_version 与数据库结构不改变。
