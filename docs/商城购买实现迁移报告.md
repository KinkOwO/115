# DFO 115us 商城购买（CeraShop CMD64）实现迁移报告

> 用途：将「商城购买冻结」修复迁移到干净工作区的自包含交接文档。
> 所有协议字段均以权威 IDB `client/DFO.exe.i64`（115 级客户端）的原生读取链
> 与 2026-09-16 实机抓包为唯一真源，未从参考服搬运字节。本文不依赖本地文件是否损坏。

---

## 1. 问题与根因

- **现象**：打开商城点购买并确认后，客户端卡在弹窗
  `Processing your purchase... Please wait.`，无法继续。
- **根因**：服务端 `cmd/wireprobe` 从未处理商城购买命令 **CMD64**
  （`ENUM_CMDPACKET_BUY_CERASHOP_ITEM`）。请求被采样层记录后直接丢弃，
  客户端等不到应答，永久停在处理中弹窗。
- **关键澄清**：历史文档把购买误判为 CMD1302。CMD1302 实际是**登录期账号名上报**
  （32 字节 UTF-16LE 账号名，无应答处理器），与商城无关。
- **客户端余额闸门不拦截**：购买前客户端本地校验
  `sub_1408829C0`（`账号点券 − Σ(数量×单价) ≥ 0` 才发包）。
  实测账号点券 100,000，远高于商品价，故闸门放行、CMD64 确实发出。

## 2. 协议证据（字节级）

### 2.1 S2C 应答统一封装格式（全客户端标定）

包有 **16 字节头**，读取游标从 +16 起。`kind==1`（应答）时：

1. 先读 **u8 成功标志**（读取函数 `sub_146EA09F0`）
2. 仅当标志为 0 时再读 **u16 错误码**（`sub_146EA1920`）；成功时无此字段
3. 查注册表调处理器 `sub_14599D200` → 各命令处理器消费分支体

| 方向 | 格式 |
| ---- | ---- |
| 成功 | `u8 非0` + 处理器分支体（**无** u16 code） |
| 失败 | `u8 0` + `u16 code` + 处理器分支体 |

读取函数标定（全部小端直读游标，越界读 0）：
`146EA09F0`=u8、`146EA1920`=u16、`146EA0BA0`=u32。

### 2.2 C2S CMD64 请求布局（`ENUM_CMDPACKET_BUY_CERASHOP_ITEM` = 64 = 0x40）

- 发送者：`sub_146A6ABF0`（购物车结算组包），由 `sub_146A6F8B0` 调用（结算入口，
  组包后立即 `sub_146D75AF0` 发送，并把窗口对象置为「购买进行中」状态）。
- 逐字段布局（小端）：

```
u8  flag                 // 窗口字段 +21748（观察值 0）
u8  mode                 // 窗口字段 +21744：1 => 后跟优惠码 wstring + u8
[u32 len + bytes + u8]   // 仅当 mode==1
u8  count                // 购物车条目数
count × {
  u8  field36            // 物品结构 +36（观察值 0）
  u8  field72            // 物品结构 +72 低字节（观察值 0）
  u32 goodsId            // 商品目录 id（本例 3000126）
  u32 amount             // 原生写入常量 1
  u8  opt1Count, opt1Count × (u32, u8)       // 时装选项表 1（sub_145F58E70）
  u8  opt2Count, opt2Count × (u32, u16, u16) // 时装选项表 2
  // 非时装商品写 opt1Count=opt2Count=0，与非时装分支的两个尾 0 字节编码相同
}
```

- **实机抓到的真实包体（16 字节）**：
  `00 00 01 00 00 3e c7 2d 00 01 00 00 00 00 00 00`
  解析：flag=0，mode=0，count=1；
  单条目 field36=0、field72=0、goodsId=`0x002DC73E`=**3000126**、amount=1、
  时装选项表均空、尾随 1 个 0 字节（静态轨迹未解释，解码层作宽容处理）。

### 2.3 CMD64 应答处理器 `sub_145267D40`

- 注册点 `0x1452a23cb`，注册器 `sub_1459A2FB0`，RTTI
  `CMDFUNC_ENUM_CMDPACKET_BUY_CERASHOP_ITEM`。
- 成功分支读取序列（flag=1 已读，随后逐字段）：

| 序号 | 类型 | 处理器读取点 | 字段语义 |
| --- | --- | --- | --- |
| 1 | u8 | `0x145267dae` | v56 子标志（处理器未使用） |
| 2 | u32 | `0x145267db7` | v66 分类（-1 = 全目录安全查找，已实机验证） |
| 3 | u32 | `0x145267dc1` | **v63 = goodsId**（清待结算记录、授所有权） |
| 4 | u32 | `0x145267dca` | v65（与 v58 比较） |
| 5 | u32 | `0x145267dd4` | v58（与 v65 比较） |
| 6 | u32 | `0x145267dde` | v64（未使用） |
| 7 | u16 | `0x145267e0a` | count 结果行数 |
| 8 | count×(u32,u32) | `0x145267e35/e3e` | 结果行（v62 变、v63 恒） |
| 9 | u32,u32 | `0x145267e8b/e94` | 仅当 v65==v58；v62≠-1 时调 `1446EDE80` |
| 10 | u32 | `0x145267ec5` | v60（所有者条目类型过滤器，-1=任意） |
| 11 | u32 | `0x145267ede` | v68（`sub_140876140` 中未用） |
| 12 | u32 | `0x145267ee8` | **v61 高半**（仅失败文本路径用） |
| 13 | u32 | `0x145267ef2` | **v61 低半 = settled 已结算数** |
| 14 | u8 | `0x145267eff` | v57 所有者条目标记 |

- 关键消费链：
  - `sub_140887530`(`CeraShopManager::onRecvPurchase`) 用 `(goodsId=v63, v60, settled=lo(v61))`：
    从待结算表按 goodsId 查记录，settled==记录数则**清除该记录**，
    否则按 settled 递减；随后 `settled` 次循环从购物车移除对应商品。
  - `sub_140876140` 用 `lo(v61)=settled` 累加**已购买商品数**。
  - **当 `v65 == v58`** 触发完整解锁：读取第 9 组附加字段、
    `sub_144705180(wnd,1,v66)` 清空购物车展示，
    `sub_1408874E0(mgr,1)` → `sub_1408873C0` **释放 Processing 处理锁**。

> **冻结破局核心**：成功包中 `lo61（settled）` 必须等于购买数量（1），
> 且 `v65==v58`（本例均 0）必须成立；否则客户端不清待结算记录、不释放 UI 锁，
> 表现为永久卡死。这与外部流传的「已结算数量发 0 导致锁死」的结论一致。

### 2.4 CMD64 失败应答布局（flag=0 时）

```
u8  0        // 失败标志（分发器已读）
u16 code     // 错误码（分发器已读）
u8  v56
u32 v58
u32 hi(v61)
u32 lo(v61)
u32 v60
u32 v64
```

合计 20 字节（含分发器读掉的 3 字节）。

### 2.5 错误码语义（`sub_145267D40` switch → dstr 文案）

| code | dstr | 文案 |
| --- | --- | --- |
| 1 | 264 | Transaction information error. |
| 11 | 258 | **Not enough CERA.** |
| 20 | 253 | **Unavailable for purchase.** |
| 25 | 263 | Billing server error. |

本实现采用的映射：

- 请求损坏 → code 1（dstr 264）
- 余额不足 → code 11（dstr 258）
- 商品不存在 → code 20（dstr 253）
- 内部错误 → code 25（dstr 263）

## 3. 商品目录（价格真源）

- **来源**：`client/Script.pvf` 内 `etc/(r)cerashop.etc`（客户端唯一真实在售目录；
  服务端此前无任何商城目录）。
- **提取方式**：项目已有工具
  `server/work/bin-tools/pvfinspect.exe -source server/work/client-build/Script.inner.pvf -files "etc/(r)cerashop.etc"`。
- **行格式**（`[item]`/`[item second]`/`[avatar]` 等商品段通用）：
  `goodsId template qty f3 f4 price f7 f8 \`name\` ...`，
  **price 为第 6 个数值 cell**（已多组抽查一致）。
- **导出产物**：`configs/cerashop.json`，共 **1362** 项，结构：
  `{ "source": ..., "source_sha256": ..., "goods": { "<id>": {template, qty, price, name, section} } }`。
- **关键实测商品**：`3000126` = `Fatigue Recovery Potion(30)`，
  单价 **50** 点券，template **10000541**，qty 1。

## 4. 数据库迁移 DDL（存档向前兼容，纯累加）

```sql
-- 账号级已购商品总账（与点券同为账号级）
CREATE TABLE IF NOT EXISTS cerashop_owned(
  account_id bigint NOT NULL REFERENCES accounts(id),
  goods_id   bigint NOT NULL,
  template   bigint NOT NULL,
  owned      bigint NOT NULL DEFAULT 0 CHECK(owned >= 0),
  updated_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (account_id, goods_id)
);

-- 购买审计流水
CREATE TABLE IF NOT EXISTS cerashop_purchases(
  id         bigserial PRIMARY KEY,
  account_id bigint NOT NULL REFERENCES accounts(id),
  goods_id   bigint NOT NULL,
  template   bigint NOT NULL,
  amount     bigint NOT NULL,
  unit_price bigint NOT NULL,
  total_price bigint NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

- 扣点使用现有 `account_currency` 账本（`cera bigint CHECK(cera>=0)`）。
- **扣款 SQL**（防透支与并发竞态的核心，卫语句放在 UPDATE 内）：

  ```sql
  INSERT INTO account_currency(account_id, cera) VALUES($1, 0)
    ON CONFLICT (account_id) DO NOTHING;
  UPDATE account_currency SET cera = cera - $2, updated_at = now()
    WHERE account_id = $1 AND cera >= $2
    RETURNING cera;   -- 无行返回 => ErrInsufficientCera
  ```

- 已购累加：

  ```sql
  INSERT INTO cerashop_owned(account_id, goods_id, template, owned)
    VALUES($1, $2, $3, $4)
    ON CONFLICT (account_id, goods_id) DO UPDATE
      SET owned = cerashop_owned.owned + $4, updated_at = now()
    RETURNING owned;
  ```

- 三张表在**同一事务**内：claim → 扣点券 → 累加已购 → 记流水 → commit，
  任一失败整体回滚。

## 7. 局限与后续（未闭环，切勿冒充已完成）

1. **多商品购物车**：成功应答的 `u16 结果行` 逐行语义（`1446EDF00` 结果面板）未完全
   归一到可安全编码的程度，当前对 `count != 1` 礼貌拒绝（code 1，
   客户端会弹错并释放锁，不产生错误状态）。后续需针对多商品实机抓包闭环。
2. **CMD252**（`ENUM_CMDPACKET_BUY_CERASHOP_LIMIT_ITEM`，单件限购直购路径）
   未实现；用户流程走的是 CMD64，不影响本修复。
3. **CMD63**（`ENUM_CMDPACKET_CERA`，0 字节点券余额刷新请求）未实现应答；
   购买后客户端主动发 CMD63 请求余额，当前不回会导致**购买后余额显示暂时不刷新**，
   需重新选角/重登才见新余额（与既有「充值要重启+重选角」限制同源）。
   参考线索（90 级版本，仅线索非真源）：应答体 `u8 1, i32 cera, u32 0, u32 0`；
   115 客户端该命令的应答处理器尚未定位，禁止直接照搬。
4. **物品入背包**：本修复完成后商品计入商城「已购」列表（`cerashop_owned` 对应的
   客户端展示）；实际提货入背包走 `CMD363 ENUM_CMDPACKET_CASH_INVENTORY` 家族，
   属另一系统，未实现。
5. **请求尾随 1 字节**：实机包体比静态发送轨迹推算多 1 个 0 字节，解码层已宽容处理
   并记录在案；如后续出现解析歧义需用 x64dbg 在发送点动态复核。
