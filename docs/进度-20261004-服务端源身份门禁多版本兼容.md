# 进度-20261004-服务端源身份门禁的多版本客户端兼容

## 背景
新客户端 2.38.3.25 的内层 PVF 生成成功后，网关启动与选角接连被三处**内容哈希门禁**拒绝。这些门禁把"脚本原始字节 SHA256"当作身份，而 PVF 脚本字节里嵌的是**字符串池偏移**——Neople 每次重建字符串池（哪怕内容 token 级完全一致）所有脚本哈希整体漂移。这与 next146（savecontract 包）自己立下的原则（"存档身份不得依赖客户端资源哈希；玩家换客户端 ⇒ 不受影响"）直接冲突。

## 每处的处置（先审计后放行）

### 1. 无色小晶块 3037（`internal/inventory/clear_cube.go`）
- 现象：启动即 `PVF candidate catalogs: clear cube source mismatch`。
- 审计：`stackable/material/cubepiece_clear.stk` 两版 33 token 解析后全等，仅 type 3/6/8 池偏移不同。
- 处置：硬编码单 SHA 改为已审计哈希集合 `clearCubeScriptSHA256s`（c6b47f4d…=2.38.2.34 汉化 / 744fe805…=2.38.3.25 原版）。

### 2. 奥德赛成长表（`internal/catalog/odyssey.go`）
- 现象：clear cube 过后 `PVF candidate catalogs: Odyssey source mismatch`。
- 审计：`contents/2026/aradodyssey/etc/aradodyssey.etc` 两版 800 token 全等。
- 处置：同上，`odysseyGrowthSHA256s` 集合（638e71ab… / 0b310543…）。

### 3. 启示录 .ctp（`internal/catalog/apocalypse.go`）——**无需修改**
- 审计：`apocalypse.ctp` 与 `dungeonskillinfo.ctp` 两版**字节级相同**（d560876f… / 4353c3fb… 与常量一致）。用临时 Go 测试（已删）做 `ImportApocalypse` 语义 diff 亦 SEMANTIC EQUAL。

### 4. 角色存档源身份（`internal/character/` 四处）——**语义修复**
- 现象：选角被拒 `select_rejected: automatic skill source mismatch`。
- 根因：`characters` 域原生导入后，`Catalog.Professions[*].RawSHA256` 来自新归档（ddb44f5d…→1b1c55d5… 等），而角色 state JSON 里建角时存的 `source_sha256` 是旧归档值。库内 4 角色（atswordman/archer/atgunner）全部命中。
- 审计：三个 .chr 两版 token 级全等（1504/1321/1392 token，0 diff）。
- 处置：四处门禁（automatic_skills.go×2 / advancement.go / progression_state.go / swordmaster_pilot.go）由 `prof.RawSHA256 != state.SourceSHA256` 改为 **`prof.Path != state.SourcePath`（L2 引用身份）**，`SourceSHA256` 字段保留（建角仍写入，仅不再做拒档依据）。这正是 savecontract 注释里"L1 存档身份用契约、L2 引用完整性按 ID 查表"的既定分级。
- 同步修了 15 个测试 fixture（补 `SourcePath: p.Path`）与 1 个 wireprobe 测试（`catalog.Profession{Path:…}`）。
