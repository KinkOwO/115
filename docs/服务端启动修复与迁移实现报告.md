> 说明：本报告基于本次会话的排查与修复过程整理，目标是作为迁移实施依据，不依赖本地已损坏的项目文件。

## 一、背景与目标

项目为 DFO 115 级本地/局域网模拟服务端。文档中原始工作区位于 `D:\115us`，迁移到新环境后客户端实际位于 `F:\wip\dof\115US`，工程根目录位于 `F:\projects\agents\reverse\115us`。

迁移后出现的核心问题：**服务端无法正常启动并被立即终止**。表现为 `launch_local.py` 报 `Startup stopped`，底层 game gateway 刚拉起即在数秒内被杀掉。

本次目标：

1. 定位服务端启动失败根因。
2. 修复启动编排脚本与配置。
3. 增加纯服务端常驻启动能力与一键启动入口。
4. 形成可迁移、可复现的实施报告。

## 四、故障根因分析

### 4.1 根因一：probe.exe 硬编码路径门

`probe.cpp` 入口 `wmain` 中有硬编码路径校验：

```cpp
if(!under(root, fs::path(L"E:\\codex\\2026-09-10\\zhe\\work")) || !fs::exists(target)) return 3;
```

`root` 为 argv[1]，即客户端目录（环境变量 `DFO_CLIENT_DIR`，值为 `F:\wip\dof\115US`）。由于该路径不在硬编码根下，`probe.exe` 直接返回退出码 `3`，且**未创建任何日志文件**（`client.log` 不存在）。

> 注：仓库内旧 `probe.exe`（分离自更早构建）曾带 `D:\115us` / `D:\115US` 路径，但迁移前二进制已重编，实际二进制内不含 `codex` 字符串；真正的硬编码在 `probe.cpp` 源码里，编译后的二进制用 `D:\115us` 作为根（由字符串表 `0x6e170/0x6e180` 可见 `DFO.exe` + `D:\115us`）。

### 4.2 根因二：非管理员环境下 WFP 硬性失败

`probe.exe` 使用 Windows Filtering Platform（WFP）做非回环网络隔离，需管理员权限。原逻辑：

```cpp
if(!guard.init()) return 4;   // FwpmSubLayerAdd0 → 0x5 (拒绝访问)
if(!guard.add(selfbuf)) return 5;
...
if(!guard.add(e.path())) return 6;
```

实测非管理员下 `FwpmSubLayerAdd0` 返回 `0x5`（ERROR_ACCESS_DENIED），`guard.init()` 直接失败并返回退出码 `4`。

另外 `launch_local.py` 中原有的管理员权限校验行被注释掉：

```python
# if not ctypes.windll.shell32.IsUserAnAdmin():raise RuntimeError(...)
```

导致非管理员环境下脚本不会提前报错，而是把失败推到 `probe.exe` 内部。

### 4.3 根因三：编排脚本联动杀进程（真正的“服务端秒挂”元凶）

`channel_probe.py` 末尾：

```python
try:
    ...
    probe = subprocess.Popen([probe.exe, ...])
    (out/'run.json').write_text(...)
    probe.wait(...)
finally:
    server.terminate(); server.wait(timeout=5)  # ← 元凶
```

当 `probe.exe` 因根因一/二快速退出（返回 3 或 4），`probe.wait()` 立即返回，随后 `finally` 执行 `server.terminate()`，将**刚拉起的 `wireprobe-dungeon39.exe` 立即杀掉**。`launch_local.py` 侧又因 `process.poll() is not None` 先于 `run.json` 就绪判断而报 `Startup stopped`。

因此表面现象是“服务端启动失败”，本质是 **probe.exe 前置失败触发服务端被连锁终止**。

## 五、修复内容

### 5.1 `server/work/dfo_probe_tools/probe.cpp`（核心）

1. **解除硬编码路径门**，只校验目标 DFO.exe 是否存在：

```cpp
if(!fs::exists(target)) return 3;
```

1. **WFP 优雅降级**：具备管理员权限则启用 WFP + 网络自检；无权限则记录日志并继续拉起客户端，不再因 WFP 失败而整体退出：

```cpp
Guard guard;
bool wfp_ok = guard.init() && guard.add(selfbuf);
if(wfp_ok){ /* 遍历根目录 .exe/.aes 添加过滤器，失败则置 wfp_ok=false */ }
if(wfp_ok) log(L"WFP_READY ...");
else       log(L"WFP_NOT_AVAILABLE_RUNNING_WITHOUT_ISOLATION");

// 网络自检仅在 wfp_ok 时执行；失败只记录，不再 return 10
```

### 5.2 `server/work/dfo_probe_tools/probe.exe`

使用 MSVC 重新编译（工具链见 §6），产物大小由 `584704` → `645632`（Git LFS 指针随之更新）。重编后行为验证：

| 输入 | 退出码 |
| --- | --- |
| 无参数 | 2 |
| 不存在的客户端目录 | 3 |
| 真实客户端目录（存在 DFO.exe） | 0 |

### 5.3 `server/work/dfo_probe_tools/channel_probe.py`

新增 `server-only` 模式：

```python
server_only = len(sys.argv)>2 and sys.argv[2]=='server-only'
...
if server_only:
    (out/'run.json').write_text(json.dumps({'server_pid':server.pid,'port':port}))
    print(f'Server listening on 127.0.0.1:7001 and {state["address"]}')
    try: server.wait()
    except KeyboardInterrupt: pass
    sys.exit(0)
```

并将 `finally` 中的杀进程改为仅在进程仍存活时执行：

```python
finally:
    if server.poll() is None:
        server.terminate(); server.wait(timeout=5)
```

### 5.4 `server/work/dfo-lan/scripts/launch_local.py`

1. 新增 `--server-only` 参数。
2. `--server-only` 下依赖检查只要求 `helper` 与 `binary`，不再要求客户端/`probe.exe` 文件存在。
3. 轮询顺序修正：**先判断 `run.json` 就绪，再判断 `process.poll()` 退出**，消除就绪态与退出态的竞态：

```python
for _ in range(300):
    if (out/'run.json').exists():
        # server-only → 打印 PID；否则印客户端已拉起
        return
    if process.poll() is not None:
        raise RuntimeError('Startup stopped; ...')
    time.sleep(.1)
```

1. 保留/恢复管理员权限校验说明（未强制，WFP 已降级处理）。

### 5.5 `stop_environment.py`（迁移通用修复）

1. 移除硬编码 `D:\115us`，改为 `pathlib.Path(__file__).resolve().parent` 动态定位。
2. 增加 UTF-8 stdout reconfigure 与配置缺失/异常保护。
3. 对 `postgres_bin`、`postgres_data` 做存在性判空。

### 5.6 新增 `启动服务端.cmd`（根目录）

一键拉起 PostgreSQL + game gateway（不含客户端），`--server-only` 模式，服务常驻，窗口关闭不影响后台服务。

## 十、注意事项与约束

1. **管理员权限**：WFP 网络隔离需要管理员；`启动游戏.cmd` 会自动提权。本次已让 `probe.exe` 在无权限时可降级运行（仅失去防连外网隔离），不阻塞启动。
2. **端口 7001**：迁移环境需确保 7001 空闲，否则 `launch_local.py` 报 `Port7001 in use`。
3. **回环多 IP**：游戏 TCP 使用 `127.0.0.2`（区别于频道 `127.0.0.1`），需系统支持 127.0.0.0/8 回环段（Windows 默认支持）。
4. **Git LFS**：`probe.exe` 与大量大文件走 Git LFS；迁移时需保证 LFS 指针与实际对象一致，否则二进制“损坏”。
5. **存档最高优先级**：`runtime/storage/pgdata` 为角色/物品实际存档，迁移备份优先保障其完整性。
6. **回滚**：原 `probe.exe` 可重新由 `git checkout` 恢复；`probe.cpp` 修改已留存 diff。
