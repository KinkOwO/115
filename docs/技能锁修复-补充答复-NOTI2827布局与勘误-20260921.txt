------------------------------------------------------------
一、NOTI2827（UNIFIED_OPTION_CHARAC）整包布局
------------------------------------------------------------
整包就是一个 3539 字节的块，结构 = 若干“按 subtype 排列的定长对象”。
随附文件：NOTI2827-角色选项默认模板-3539.bin（即客户端默认空模板，3539 字节）。
服务端做法：复制该模板 → 只改技能锁对象 → 原样作为 NOTI2827 推送，其余字节
（含所有你们没有数据的字段）保持模板默认值即可，客户端会正常消费。

★ 技能锁相关对象（两个，紧邻，均为 386 字节，建议两个都填同样数据）：
  subtype 19（0x13，技能锁 SET_UNIFIED_OPTION 的 subtype）
      对象在整包偏移 2736，占用 2736..3121（386 字节）
  subtype 20（0x14，与 19 共用客户端同一个锁处理函数）
      对象在整包偏移 3122，占用 3122..3507（386 字节）
  实测：两个对象都填充（即 mode=3）才能在重选角色 / 重启后完整恢复；
        只填 2736 在部分情况下锁会不全。两者填同样的锁数据，安全且已验证。
  注意：subtype 18 在偏移 2716，只有 20 字节，不是锁块，不要写到这里。

★ 每个 386 字节对象的内部布局（以对象起点 obj 为基准）：
  obj+0        u8    valid（有锁=1；空模板=0）
  obj+1        u8    保留（空模板=0；填充时保持 0）
  obj+2        128 个 u16 槽（256 字节），双页，每页 64 槽：
                 槽 0..63（全局 position 0..63）：槽值 = 全局技能ID（ID < 512）
                 槽 64..127（全局 position 64..127）：槽值 = 全局技能ID - 512
                 空槽 = 0xFFFF
  obj+258      128 个 exist 字节：该槽有锁=1，无锁=0
  校验：2(头) + 256(u16) + 128(exist) = 386；2736+386 正好 = 3122。

★ 空模板默认值（随附文件即此状态）：valid=0，128 个 u16 全 0xFFFF，exist 全 0。

二、填充步骤（语言无关；可直接照做）
------------------------------------------------------------
输入：要恢复的“全局技能ID集合” S。
1) p = 复制 3539 默认模板。
2) 分页并升序：
     page0 = sorted( id in S if id < 512 )
     page1 = sorted( id-512 for id in S if 512 <= id < 1024 )
3) 对每个对象起点 obj ∈ {2736, 3122}：
     p[obj+0] = 1
     for i,id in enumerate(page0):
         u16@ p[obj+2 + 2*i]      = id
         p[obj+258 + i]           = 1
     for k,m in enumerate(page1):
         slot = 64 + k
         u16@ p[obj+2 + 2*slot]   = m
         p[obj+258 + slot]        = 1
   （其余槽保持 0xFFFF、exist 保持 0。每页最多 64 个，超出丢弃。）
4) 把 p 作为 NOTI2827 推送。

★ 发送时机（不变，最容易导致闪退）：
  NOTI2827 必须放在“进入城镇整组数据帧的最后”——在快捷栏 NOTI376 之后、
  所有技能/背包/区域/任务等数据帧之后。位置过早会在进城后约 0.3~1 秒崩溃，
  与锁块内容是否正确无关。
  （实测完整恢复时，NOTI376 内也带了一份“升序技能ID、0xFFFF 终止”的列表，
   偏移 260；它不是决定性的，决定性的是 NOTI2827 双对象 + 上述发送时机。）

三、两处勘误（你们正确，原说明书对应条目作废）
------------------------------------------------------------
■ 勘误1：CMD682
  - 数值换算上 682 = 0x2AA 没错，但权威 opcode 表中
      0x2AA = ENUM_CMDPACKET_STATICS_RUNTIME_TING（与“依赖2827的锁流程”无关）；
      0x682 = ENUM_CMDPACKET_ARAD_ROYAL_RUMBLE_SET_QUICKSLOT。
  - 我们在完整 next37 双向抓包里统计了全部客户端上行 opcode，客户端
    “从未”发出 682（最接近的是 684=RESERVE_LEAVE_PARTY，也无关）。
  - 结论：原说明书“CMD682，进城后约1秒、严格依赖2827发出”该条作废。
    推送 NOTI2827 不需要等待或依赖任何额外的客户端回包；也不要用它做触发。

■ 勘误2：+04（以及 +00）字段
  - 这两个 u32 在不同 subtype / 帧类型下取值不同，不是常量：
      技能锁帧（subtype=0x13）实测：+04 多为 01 00 00 00；+00 为 01/03 等
        批次/类型值（不是随机时间戳，也不固定为 01）。
      系统设置帧（subtype=0x05）实测：+04 出现 00 00 00 00、01 00 00 00、
        FA 7F 00 00；+00 多为随机数。
  - 结论：解析技能锁时“不要读取、也不要校验” +00/+04，直接忽略这 8 字节，
    从 +14 的 subtype 开始解析（subtype@+14、count@+15、条目@+19）。
    把它们当 01 常量校验会漏帧。

四、IDA 逆向方法（补齐对方 AI 指出缺失的部分）
------------------------------------------------------------
我们使用的是“脱壳后的静态分析镜像”（ImageBase = 0x140000000）。同版本客户端
下列地址可直接用；版本不同时按“定位方法”自行复核，偏移会变但找法不变。

■ 关键函数地址（脱壳镜像）
  NOTI2827 处理函数            sub_1403E0120
  NOTI2826 处理函数            sub_1403E0030
  NOTI2828 处理函数            sub_1403DFE80
  CMD2377 处理入口             sub_1403DFE10
  3539 块“按 subtype 定位”     sub_14757B0C0   ← 偏移真源（看它的 switch）
  3648 块“按 subtype 定位”     sub_14757AE50
  锁“单条写入”（证实布局）      sub_1403DCC50
  锁读取 / 默认块构造           sub_1403D37E0
  锁保存辅助                    sub_1403D6660

■ 3539 块完整 subtype→偏移表（直接读自 sub_14757B0C0 的 switch）
  subtype 3→0    4→473   5→946   6→1467  7→1988
  10→2600  12→2605  13→2637  14→2648  15→2659
  16→2670  17→2693  18→2716(20B)  19→2736(386)  20→3122(386)
  22→3508  23→3521  24→3529  25→3534
  （相邻偏移之差即该对象长度；19/20 之差恰为 386。）

■ 版本不一致时的定位方法（逐步）
  1) 先得到脱壳镜像：Themida 加壳，需在运行到 OEP 后 dump、修复 IAT，再载入 IDA。
     （本修复不依赖可运行的脱壳 EXE，静态镜像即可用于读结构。）
  2) 找 NOTI2827 处理函数：在 NOTI 分发表里找引用立即数 0xB0B 的项，跟到处理函数；
     函数内会出现长度立即数 3539（0xDD3）和一次“按 subtype 解析”的调用。
  3) 跟进去就是“按 subtype 定位”函数：它是一个 switch，每个 case 形如
     `obj = 块基址 + 固定偏移`，这些固定偏移即整包内各 subtype 的偏移（零猜测）。
  4) 证实锁块内部布局：找锁的单条写入函数，可见
       *(u16*)(obj + 2 + 2*position) = 值;
       *(u8* )(obj + 258 + position) = 1;
     双页公式特征：对全局ID做 ±512（立即数 0x200）的加/减，配合 position>=64 判断。
  5) 找发送时机：在客户端进城初始化里，确认锁块对象在快捷栏等对象之后才被读取，
     从而确定服务端必须最后推送。
