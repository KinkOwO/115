## 4. `npk.index` 两次安装失败的根因（本次最重要的技术结论）

两个**独立** bug，都会让这一步失败：

### 根因 A：脚本永远找不到索引构建器

引擎 `runPackagedScript`（`115us-dfolauncher\internal\modkit\exec.go:37-48`）执行
`npk.index` 时**只把 `.ps1` 抽到 `<workDir>\.modkit-script\`** 再跑，DLL 不会跟着过去。
脚本却写 `$PSScriptRoot\PVF\tools` ⇒ 必然"包内缺少依赖"。

**修法**：`mod.json` 用引擎支持的 `{pack}` 占位符把包根传进去
（`-ToolsDir {pack}/resource/PVF/tools -PackDir {pack}`），脚本内按候选列表找 +
"从工作目录反推 mod id 扫 `mods\<id>\`"兜底。

### 根因 B：索引构建器要 .NET 10，而包内 pwsh 永远停在 .NET 8

- `USLocalServer.Pvf.dll` / `USLocalServer.Launcher.Core.dll` 的
  `TargetFrameworkAttribute` = **`.NETCoreApp,Version=v10.0`**；
  加载报 `Could not load file or assembly 'System.Runtime, Version=10.0.0.0'`。
- **真正的坑**：包内 pwsh 7.4.6 便携版是**自包含 net8**
  （目录里有 `hostfxr.dll` / `System.Private.CoreLib.dll`）。自包含应用按设计
  **忽略一切 roll-forward**。实测三种办法全部无效、一律仍是 8.0.10：
  - `DOTNET_ROLL_FORWARD=LatestMajor` + `DOTNET_ROOT`
  - 改 runtimeconfig 加 `rollForward: LatestMajor`（须先删互斥的 `rollForwardOnNoCandidateFx`）
  - `dotnet exec --fx-version 10.0.12 pwsh.dll`

**修法**：不再让 pwsh 反射。新增 `client-patchs\nuannuan.shop\idxtool\`
（C# net10，`PublishSingleFile` + `SelfContained` + `EnableCompressionInSingleFile`）
→ 37.6MB 的 `NpkIndexTool.exe` 打进包 `tools/npkidx/`；
`rebuild-index.ps1` 退化成"找工具 → 复制到 %TEMP% → 调用 → 透传退出码"。
**目标机不需要装任何 .NET 运行时。**

实测（完全按引擎调用方式，父进程仍是 net8 pwsh）：

```
构建方法 : A.h.A(String, IProgress`1, CancellationToken)
第1次 H { Outcome=A, NpkFiles=2, IndexedNpks=2, Images=11, Changes=null }
第2次 H { Outcome=B, NpkFiles=2, IndexedNpks=2, Images=11, Changes=null }
索引大小 : 274 字节 → [OK] 总数一致 / [OK] 已收敛 → exit=0
```

## 5. 扩展按钮 DLL（业主新给的 `~/Downloads/dinput8.dll`）

### 它是什么（静态 + 受控加载实测）

- **dinput8 代理**，导出 6 个函数，与客户端现有 `dinput8.dll`
  （"DFO localization proxy v2"，107,008 B）**完全一致**；实测 `DirectInput8Create` 返回 `S_OK`。
- **认得共用入口**：自己 `LoadLibrary("ChineseLocalization.dll")` 并调 `StartLocalization`
  （实测 `CLIENT_HOST started result=0`）⇒ 顶替代理不会打断中文输入 / 难度规则插件。
- 能力（自身字符串）：日志名 `115-shop-tabs.log`；`INSTALL rejected image layout` /
  `vtable slot` / `BEAST rejected actor vtable` / `AVATAR_MARKER` / `EQUIPMENT_TITLE` / `HUD_DIAG`
  ⇒ 虚表替换型增强：商城页签、怪物变身、头像标记、装备中文强化标题、HUD 诊断。
- 是暖暖商城那个 DLL 的**新版**（与 `NuanNuanShop.dll` 的 UTF-16 串 502 vs 500、交集 499）。

### 顺带查实的长期误判 ⚠️

宿主干日志 `client-host.log` 一直写着：

```
插件没有 ModStart 导出，已跳过：C:\Game\dof\115us\DFO\.115us-mods\NuanNuanShop.dll
```

即 **暖暖商城包里那个 DLL 从装上起就没执行过** —— 它没有 `ModStart`，
宿主 `run_plugin`（`client-host/src/client-host.c:92-97`）先 `LoadLibrary` 再找 `ModStart`，
找不到只记日志 return（DllMain 已跑，但它的活儿不在 DllMain 里）。
业主选择**保留**这条 op（无害），能力改由新的 `dinput8.dll` 提供。

### 落位

client 层第 7 条 op：`file.replace` → target `dinput8.dll`（客户端根，**唯一**自动加载槽位），
source `client/dinput8.dll`。modkit 会备份原文件，卸载逐字节还原成 localization proxy v2。
