### 分类判定依据（代理注入）

| 数据源 | 用途 |
|---|---|
| `configs\items.index.json`（38.6 万条） | id → kind / stack_type（材料/任务/副职业/徽章/宠物消耗品等） |

### 管理能力

- **可堆叠物品**（消耗品/材料/任务/副职业/徽章/宠物消耗品）：叠加显示数量；

- **添加道具面板**：

  - 搜索结果带**分类标签**与**可堆叠标记**；
  - 多选加入待添加列表、各自调数量，一次性发放；
  - **可堆叠物品同种自动合并到同一格**；
  - **发放后由服务端自动放入游戏内对应位置**（材料→背包物品栏、宠物→宠物栏等）。

## 五、技术实现要点

1. **不修改 gmweb 二进制**：全部功能通过本地 Python 代理（28081）实现。
2. **Token 自动注入**：代理启动时从 gmweb 首页正则抓取 `var TOKEN="..."`，转发 API 时自动携带。
3. **分类注入**：代理启动加载本地目录构建 id→分类映射；对 `/api/items` 与 `/api/character` 响应注入
   `category: {group, sub}` 与 `stackable` 标记，前端据此分类管理。
4. **页面热更新**：代理按文件 mtime 检测 `index.html` 变更，改页面无需重启代理；
   **改代理代码后需重启代理**（重启后自动重新抓取 token 并重载目录）。
5. **自动刷新恢复**：页面重建（自动刷新/发放后刷新）时自动恢复搜索状态与待添加列表，避免结果丢失。
6. **数据库操作说明**：部分服务端不支持的改动（如删除装备行、清理测试数据）通过
   `D:\115us\tools\pg\pgsql\bin\psql.exe` 直改 `characters.state`，gmweb 实时读取生效。

## 七、已知边界与说明

1. **服务端发放目录限制**：gmweb 的「物品发放」/「添加道具」只能发放
   `configs\loot.next25.json`（可堆叠物品）与 `configs\equipment.current37.json`（装备）中的物品。
   时装、徽章等**不在服务端发放目录**的物品，发放时会提示
   `equipment absent from source` 等错误，**不会产生脏数据**；已拥有该类物品的增减/管理不受影响。
   如需 GM 台也能发放，需扩展服务端发放目录。
2. **装备行删除**：服务端 `state/bag` 只支持装备行改耐久，不支持删除装备行；
   删除装备行需直改数据库（见 `dashboard\tests\clean_db.sql` 写法）。
3. **服务端能力**：`/api/state/bag` 只支持**已有行**的数量/耐久编辑；
   新增物品走 `/api/grant`（自动分配槽位）。
4. **在线角色**：服务端提示——角色在线时改动需重新选择角色（小退再进）才能看到。

## 九、启动流程整合修复（2026-09-18 追加）

### 背景问题

一键启动时出现两个 GM 界面互相抢占：

1. **28080 自动弹窗抢占焦点**：`gmweb.exe` 内置参数 `-open` 默认 `true`（启动后自动打开浏览器），
   每次启动都会弹出 `http://127.0.0.1:28080/?token=...` 页面，抢在管理台之前打开。
2. **打开地址不是目标页**：启动脚本打开的是 `http://127.0.0.1:28081/`（工作台首页），而非账号管理页。
3. **28081 失效（深层原因）**：gmweb 每次重启会生成**新 token**，代理若持有旧 token，
   28081 的 API 请求将全部返回 401，页面表现为"无法使用"。

### 修复内容

| 文件 | 修改 | 效果 |
|---|---|---|
| `scripts\gmweb.py` | gmweb.exe 启动参数追加 `-open=false` | 28080 只作静默后端，不再自动打开浏览器 |
| `dashboard\start_gm_dashboard.ps1` | 浏览器打开地址改为 `http://127.0.0.1:28081/#accounts` | 一键启动直达账号管理页 |
| `dashboard\gm_dashboard_proxy.py` | `_proxy` 增加 **401 token 自动刷新重试**（`fetch_token()` 后重发一次请求） | gmweb 重启换 token 后 28081 自动恢复，不再 401 失效 |

### 整合后行为

- **28080（gmweb 后端）**：静默运行，仅供代理转发，不弹浏览器窗口；
  直接访问 28080 的 API 需带 token（返回 401 属预期）。
- **28081（GM 管理台）**：唯一打开的界面，`http://127.0.0.1:28081/#accounts`。
- **Token 一致性**：代理转发时自动携带当前 token；后端重启换 token 后，
  代理收到 401 会自动抓取新 token 重试，无需手动重启代理。

### 验证结果（2026-09-18 实测）

| 项目 | 结果 |
|---|---|
| gmweb 命令行含 `-open=false`（28080 不弹浏览器） | ✅ |
| 一键启动仅打开 `http://127.0.0.1:28081/#accounts` | ✅ |
| 页面 HTTP 200（标题「DFO 115us · GM 管理台」） | ✅ |
| API 正常（`/api/items?q=test` 返回 60 条） | ✅ |
| 28080 直接访问 API 返回 401（需 token，代理注入正常） | ✅ |

## 十、账号管理·金币/代币发放（2026-09-18 追加）

### 功能说明

「账号管理 → 账号级发放」页升级为**账号/角色资产发放**，支持一次选择目标账号与角色，同时发放**金币**和**点券（代币）**。

| 资产 | 发放级别 | 规则 |
|---|---|---|
| 金币（gold） | **角色级** | 只能增加（≥0）；必须选择目标角色；写入 `characters.state.inventory.gold` |
| 点券（cera） | **账号级** | 可正可负（正=充值，负=扣除）；可不选角色（character=0）；写入 `account_currency.cera` |

### 交互

- **目标账号**：下拉选择（账号列表自动加载）；
- **目标角色**：切换账号时自动加载该账号的角色列表；选项含「仅账号级（不发金币）」；
- **金币**：数字输入（min=0），发到所选角色；
- **点券**：数字输入（可正可负），发到所选账号；
- **原因**：写入审计（`admin_grants.reason`）；
- 校验：发金币必须选角色；金币/点券至少填一项才可提交；
- 成功后自动刷新账号列表，Toast 提示实际发放内容。

### 实现

- 前端 `dashboard\index.html`：重写 `renderAccountGrant()`（新增金币输入框 `ag_gold`、角色必选校验、组合提交）；
- 后端能力复用 gmweb 原生 `/api/grant`（请求体 `{account, character, gold, cera, reason, items:[]}`，无需改代理与二进制）。
